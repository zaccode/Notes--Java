## **1. GRAPH REPRESENTATIONS**

### 📖 **Theory**
Graphs consist of **vertices (nodes)** connected by **edges**. The way you store a graph determines algorithm efficiency.

| Representation | Space | Edge Lookup | Iterate Neighbors | Best For |
|---------------|-------|-------------|-------------------|----------|
| **Adjacency Matrix** | O(V²) | O(1) | O(V) | Dense graphs (E ≈ V²) |
| **Adjacency List** | O(V+E) | O(degree) | O(degree) | Sparse graphs (E << V²) |
| **Edge List** | O(E) | O(E) | O(E) | Kruskal's algorithm |

### 🎨 **Visual Diagram**
```
ADJACENCY MATRIX          ADJACENCY LIST
    0  1  2  3            0 → [1, 2]
0  [0, 1, 1, 0]          1 → [0, 3]
1  [1, 0, 0, 1]          2 → [0]
2  [1, 0, 0, 0]          3 → [1]
3  [0, 1, 0, 0]
```

### 🔧 **Template Code**
```java
// Adjacency List (MOST COMMON)
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
graph.get(u).add(v);  // add edge u→v
graph.get(v).add(u);  // for undirected

// Adjacency Matrix
boolean[][] matrix = new boolean[n][n];
matrix[u][v] = true;

// Edge List (for sorting edges)
int[][] edges = new int[E][3];  // [u, v, weight]
```

## **2. BFS (Breadth-First Search)**

### 📖 **Theory**
BFS explores graph **level by level** using a queue. It finds **shortest path** in **unweighted graphs** (all edges weight = 1). BFS guarantees the first time you reach a node, you've taken the minimum number of edges.

**Key Insight**: BFS is to graphs what level-order traversal is to trees.

### 🎨 **Visual Diagram**
```
Start: Node 0                           Queue: [0]
   0                                    Visited: {0}
  / \
 1   2                                 Level 0: 0
 |   |
 3   4                                 Level 1: 1, 2
                                       Level 2: 3, 4

BFS Order: 0 → 1 → 2 → 3 → 4
```

### 🔧 **Template Code**
```java
// BFS for shortest path (unweighted)
public int[] bfs(int n, List<List<Integer>> graph, int start) {
    int[] dist = new int[n];
    Arrays.fill(dist, -1);
    Queue<Integer> queue = new LinkedList<>();
    
    dist[start] = 0;
    queue.offer(start);
    
    while (!queue.isEmpty()) {
        int u = queue.poll();
        for (int v : graph.get(u)) {
            if (dist[v] == -1) {  // not visited
                dist[v] = dist[u] + 1;
                queue.offer(v);
            }
        }
    }
    return dist;
}
```

### 🎯 **When To Use BFS**
- Shortest path in unweighted graph
- Level-order traversal
- Finding connected components
- Word ladder problems
- Rotting oranges (multi-source BFS)

### 🔄 **BFS vs DFS Comparison**

| Aspect | BFS | DFS |
|--------|-----|-----|
| **Data Structure** | Queue | Stack (or recursion) |
| **Shortest Path** | Yes (unweighted) | No |
| **Space** | O(width) | O(depth) |
| **When to Use** | Shortest path, level order | Backtracking, topological sort, cycle detection |

## **3. DFS (Depth-First Search)**

### 📖 **Theory**
DFS explores as far as possible along each branch before backtracking. Uses recursion (implicit stack) or explicit stack. Perfect for **path exploration**, **backtracking**, and **connectivity** problems.

### 🎨 **Visual Diagram**
```
    0                               DFS Order (pre-order):
   / \                              0 → 1 → 3 → 2 → 4
  1   2
  |   |
  3   4

Recursive visualization:
dfs(0) → dfs(1) → dfs(3) → backtrack → dfs(2) → dfs(4)
```

### 🔧 **Template Code**
```java
// DFS - Recursive
boolean[] visited = new boolean[n];

public void dfs(int u, List<List<Integer>> graph) {
    visited[u] = true;
    for (int v : graph.get(u)) {
        if (!visited[v]) {
            dfs(v, graph);
        }
    }
}

// DFS with explicit stack (avoid recursion limit)
public void dfsIterative(int start, List<List<Integer>> graph) {
    Stack<Integer> stack = new Stack<>();
    boolean[] visited = new boolean[n];
    stack.push(start);
    
    while (!stack.isEmpty()) {
        int u = stack.pop();
        if (!visited[u]) {
            visited[u] = true;
            for (int v : graph.get(u)) {
                if (!visited[v]) stack.push(v);
            }
        }
    }
}
```

### 🎯 **When To Use DFS**
- Detecting cycles
- Topological sorting
- Finding connected components
- Solving puzzles/mazes
- Path existence checking
- Backtracking problems

## **4. CYCLE DETECTION**

### 📖 **Theory**
Detecting cycles is critical for **deadlock detection**, **dependency validation**, and ensuring algorithms like topological sort can run.

**Undirected Graph**: A cycle exists if during DFS, you find an edge to an already visited node that is NOT the parent.

**Directed Graph**: Use **3-state coloring** (0=unvisited, 1=visiting/in-stack, 2=processed). A back edge to a node in state 1 indicates a cycle.

### 🎨 **Visual Diagram**
```
UNDIRECTED CYCLE               DIRECTED CYCLE
    0                               0 → 1
   / \                              ↑   ↓
  1   2                             3 ← 2
  |   |                             (0→1→2→3→0)
  3   4
Edge 1-3 creates cycle? NO (tree)
Edge 2-4 creates cycle? NO (tree)
Edge 1-2 creates cycle? YES (0-1-2-0)

DETECTION: Back edge to visited non-parent = cycle
```

### 🔧 **Template Code**
```java
// Cycle Detection in Directed Graph (3-state coloring)
public boolean hasCycle(int n, List<List<Integer>> graph) {
    int[] state = new int[n];  // 0=unvisited, 1=visiting, 2=processed
    
    for (int i = 0; i < n; i++) {
        if (state[i] == 0 && dfsCycle(i, graph, state)) {
            return true;
        }
    }
    return false;
}

private boolean dfsCycle(int u, List<List<Integer>> graph, int[] state) {
    state[u] = 1;  // currently in recursion stack
    
    for (int v : graph.get(u)) {
        if (state[v] == 1) return true;  // back edge found
        if (state[v] == 0 && dfsCycle(v, graph, state)) return true;
    }
    
    state[u] = 2;  // fully processed
    return false;
}
```

### 🎯 **When To Use**
- Course Schedule (prerequisites)
- Deadlock detection
- Validating DAG before topological sort
- Finding redundant connections

## **5. TOPOLOGICAL SORT**

### 📖 **Theory**
Topological sort orders nodes in a **DAG** so that for every edge u→v, u comes before v. Used for **task scheduling**, **build systems**, and **dependency resolution**.

**Two approaches:**
- **Kahn's Algorithm (BFS)**: Remove nodes with in-degree 0
- **DFS-based**: Post-order DFS + reverse

### 🎨 **Visual Diagram**
```
DAG: 0 → 1 → 3     Kahn's Algorithm:
     ↓   ↓         Step 1: In-degrees: 0:0, 1:1, 2:0, 3:2
     2   → 4       Queue: [0, 2]
                   Remove 0 → reduce in-degrees: 1:0, 2:1
Order: 0, 2, 1, 3, 4
```

### 🔧 **Template Code**
```java
// Kahn's Algorithm (BFS)
public int[] topologicalSort(int n, List<List<Integer>> graph) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++) {
        for (int v : graph.get(u)) inDegree[v]++;
    }
    
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) queue.offer(i);
    }
    
    int[] result = new int[n];
    int idx = 0;
    while (!queue.isEmpty()) {
        int u = queue.poll();
        result[idx++] = u;
        for (int v : graph.get(u)) {
            if (--inDegree[v] == 0) queue.offer(v);
        }
    }
    return idx == n ? result : new int[0];  // empty if cycle exists
}
```

### 🎯 **When To Use**
- Course schedule problems
- Build order (compilation dependencies)
- Alien dictionary (character ordering)
- Task sequencing

## **6. DIJKSTRA'S ALGORITHM**

### 📖 **Theory**
Dijkstra finds **shortest paths** from source to all nodes in **weighted graphs with NON-NEGATIVE weights**. Uses a **priority queue** (min-heap) to always expand the node with smallest known distance.

**Core principle**: Relaxation + greedy. Once a node is popped from PQ, its distance is final (Dijkstra's claim).

### 🎨 **Visual Diagram**
```
Graph: 0 --4--> 1 --1--> 3
       |         |
       2         2
       |         |
       2 --3--> 3

Dijkstra from 0:
Step 1: PQ: (0,0) → pop 0, relax neighbors: dist[1]=4, dist[2]=2
Step 2: PQ: (2,2), (4,1) → pop 2, relax: dist[3]=5
Step 3: PQ: (4,1), (5,3) → pop 1, relax: dist[3]=min(5,4+2=6)=5
Final distances: [0, 4, 2, 5]
```

### 🔧 **Template Code**
```java
public int[] dijkstra(int n, List<int[]>[] graph, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0] - b[0]);
    pq.offer(new int[]{0, src});
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        
        if (d > dist[u]) continue;  // stale entry
        
        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    return dist;
}
```

### ⚠️ **Important**: Dijkstra fails with **negative weights** (use Bellman-Ford)

### 🎯 **When To Use**
- GPS navigation (shortest route)
- Network routing (OSPF)
- Path with minimum effort
- Any weighted graph with non-negative weights

## **7. BELLMAN-FORD ALGORITHM**

### 📖 **Theory**
Bellman-Ford finds shortest paths **even with NEGATIVE weights** and **detects negative cycles**. It relaxes all edges V-1 times (longest path without cycle has V-1 edges).

**Key Insight**: After V-1 relaxations, if another relaxation improves distance → negative cycle exists.

### 🎨 **Visual Diagram**
```
Graph with negative edge: 0 → 1 (4), 0 → 2 (3), 2 → 1 (-2)
Iteration 1: dist[1] = min(∞, 0+4=4, 0+3-2=1) = 1
Iteration 2: dist[1] = min(1, 0+3-2=1) = 1 (stable)

Negative cycle: 0 → 1 (1), 1 → 2 (1), 2 → 0 (-3)
Each iteration reduces distances infinitely → negative cycle detected
```

### 🔧 **Template Code**
```java
public int[] bellmanFord(int n, int[][] edges, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // Relax V-1 times
    for (int i = 0; i < n - 1; i++) {
        for (int[] edge : edges) {
            int u = edge[0], v = edge[1], w = edge[2];
            if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
            }
        }
    }
    
    // Check for negative cycles
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1], w = edge[2];
        if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
            return null;  // negative cycle exists
        }
    }
    return dist;
}
```

### 🎯 **When To Use**
- Graphs with negative weights
- Detecting negative cycles
- Currency arbitrage detection
- "Cheapest flights with K stops" variation

### 🔄 **Dijkstra vs Bellman-Ford vs Floyd-Warshall**

| Algorithm | Time | Negative Weights | Negative Cycle | Best For |
|-----------|------|------------------|----------------|----------|
| Dijkstra | O((V+E)log V) | ❌ No | ❌ No | Single source, non-negative |
| Bellman-Ford | O(V×E) | ✅ Yes | ✅ Detects | Single source, negative allowed |
| Floyd-Warshall | O(V³) | ✅ Yes | ✅ Detects | All pairs shortest |

## **8. FLOYD-WARSHALL ALGORITHM**

### 📖 **Theory**
Floyd-Warshall finds **shortest paths between ALL pairs** of nodes. Uses **dynamic programming**: `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])` for each intermediate node k.

**Core idea**: Consider each vertex as a potential "stopover" to improve paths.

### 🎨 **Visual Diagram**
```
Initial:            After k=0:           After k=1:           After k=2:
   0   1   2           0   1   2           0   1   2           0   1   2
0  0   ∞   5         0  0   ∞   5         0  0   9   5         0  0   9   5
1  ∞   0   2    →    1  ∞   0   2    →    1  ∞   0   2    →    1  ∞   0   2
2  5   2   0         2  5   2   0         2  5   2   0         2  5   2   0

k=0 (via node 0): 2→1 via 0? 5+∞ = no
k=1 (via node 1): 0→2 via 1? ∞+2 = no
k=2 (via node 2): 0→1 via 2? 5+2=7 (better than ∞)
```

### 🔧 **Template Code**
```java
public int[][] floydWarshall(int n, int[][] edges) {
    int[][] dist = new int[n][n];
    for (int i = 0; i < n; i++) {
        Arrays.fill(dist[i], Integer.MAX_VALUE);
        dist[i][i] = 0;
    }
    for (int[] e : edges) {
        dist[e[0]][e[1]] = e[2];
        dist[e[1]][e[0]] = e[2];  // undirected
    }
    
    for (int k = 0; k < n; k++) {
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (dist[i][k] != Integer.MAX_VALUE && 
                    dist[k][j] != Integer.MAX_VALUE) {
                    dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);
                }
            }
        }
    }
    return dist;
}
```

# 📚 **PART 4: DISJOINT SET UNION (DSU)**

## **9. UNION-FIND (DSU)**

### 📖 **Theory**
DSU efficiently manages **dynamic connectivity** - merging sets and checking if elements are connected. Two key optimizations:
- **Path compression**: Flattens the tree during find
- **Union by rank/size**: Attaches smaller tree under larger

**Time Complexity**: Nearly O(1) per operation (inverse Ackermann function)

### 🎨 **Visual Diagram**
```
Initial: 0   1   2   3   4
Union(0,1): 0→1 (1 is parent)
           2   3   4
           1
          /
         0
Union(2,3): 2→3
Union(1,3): Find(1)=1, Find(3)=3, union by rank → 1→3
           3
          / \
         1   2
        /
       0
Find(0) with path compression: 0's parent becomes 3 directly
```

### 🔧 **Template Code**
```java
class DSU {
    int[] parent;
    int[] rank;
    
    public DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    
    public int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);  // path compression
        }
        return parent[x];
    }
    
    public boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false;
        
        if (rank[px] < rank[py]) {
            parent[px] = py;
        } else if (rank[px] > rank[py]) {
            parent[py] = px;
        } else {
            parent[py] = px;
            rank[px]++;
        }
        return true;
    }
    
    public boolean connected(int x, int y) {
        return find(x) == find(y);
    }
}
```

### 🎯 **When To Use**
- Dynamic connectivity queries
- Kruskal's algorithm (MST)
- Number of connected components
- Redundant connection detection
- Accounts merge problems

# 📚 **PART 5: MINIMUM SPANNING TREE**

## **10. KRUSKAL'S ALGORITHM**

### 📖 **Theory**
Kruskal builds MST by adding smallest edges that **don't create cycles**. Uses **Union-Find** to detect cycles. Sort edges by weight, iterate smallest to largest, add if endpoints are in different components.

### 🎨 **Visual Diagram**
```
Edges sorted: (0-1:2), (2-3:3), (1-2:4), (0-3:5), (1-3:6)
Step 1: Add 0-1 (2)     Components: {0,1}, {2}, {3}
Step 2: Add 2-3 (3)     Components: {0,1}, {2,3}
Step 3: Add 1-2 (4)     Different components? YES → add
Result: MST weight = 2+3+4=9
```

### 🔧 **Template Code**
```java
public int kruskal(int n, int[][] edges) {  // edges: [u, v, weight]
    Arrays.sort(edges, (a,b) -> a[2] - b[2]);
    DSU dsu = new DSU(n);
    int mstWeight = 0, edgesUsed = 0;
    
    for (int[] edge : edges) {
        if (dsu.union(edge[0], edge[1])) {
            mstWeight += edge[2];
            edgesUsed++;
            if (edgesUsed == n - 1) break;
        }
    }
    return edgesUsed == n - 1 ? mstWeight : -1;  // -1 if disconnected
}
```

## **11. PRIM'S ALGORITHM**

### 📖 **Theory**
Prim grows MST from a **starting node**, always adding the smallest edge connecting the tree to an outside node. Uses **priority queue** similar to Dijkstra but tracks edge weights to connect new nodes.

### 🎨 **Visual Diagram**
```
Start at 0:
    PQ: (2,1), (5,3)  → pick 0-1 (2), add 1
    PQ: (4,2), (5,3)  → pick 1-2 (4), add 2
    PQ: (3,3)         → pick 2-3 (3), add 3
MST: 0-1(2), 1-2(4), 2-3(3) weight=9
```

### 🔧 **Template Code**
```java
public int prim(int n, List<int[]>[] graph) {
    boolean[] inMST = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[1] - b[1]);
    pq.offer(new int[]{0, 0});  // {node, weight to connect}
    
    int mstWeight = 0, nodesInMST = 0;
    
    while (!pq.isEmpty() && nodesInMST < n) {
        int[] curr = pq.poll();
        int u = curr[0], w = curr[1];
        
        if (inMST[u]) continue;
        
        inMST[u] = true;
        mstWeight += w;
        nodesInMST++;
        
        for (int[] edge : graph[u]) {
            int v = edge[0], weight = edge[1];
            if (!inMST[v]) {
                pq.offer(new int[]{v, weight});
            }
        }
    }
    return nodesInMST == n ? mstWeight : -1;
}
```

### 🔄 **Kruskal vs Prim Comparison**

| Aspect | Kruskal | Prim |
|--------|---------|------|
| **Approach** | Edge-based | Vertex-based |
| **Data Structure** | Union-Find | Priority Queue |
| **Best For** | Sparse graphs (E log V) | Dense graphs (V²) |
| **Initialization** | Sort all edges | Start from one node |
| **Cycle Detection** | Union-Find | Visited set |

# 📚 **PART 6: STRONG CONNECTIVITY**

## **12. KOSARAJU'S ALGORITHM (SCC)**

### 📖 **Theory**
Kosaraju finds **Strongly Connected Components** (SCCs) where every node can reach every other. Uses **two DFS passes**:
1. DFS on original graph → push nodes to stack in finishing order
2. DFS on **transposed graph** (reverse edges) using stack order

Each DFS in step 2 gives one SCC.

### 🎨 **Visual Diagram**
```
Original Graph:         Transposed Graph:
0 → 1 → 3 ← 2          0 ← 1 ← 3 → 2
↑         ↓            ↑         ↓
4 ← 5                  4 → 5

Step 1 DFS order (finishing times): push to stack
Step 2: Pop from stack, DFS on transposed:
Pop 3 → explore {3} alone? No → {3} is SCC
Pop 1 → explore {1,0,4,5} → SCC {0,1,4,5}
Pop 2 → explore {2} → SCC {2}
```

### 🔧 **Template Code**
```java
public List<List<Integer>> kosaraju(int n, List<List<Integer>> graph) {
    // Step 1: DFS to get finishing order
    boolean[] visited = new boolean[n];
    Stack<Integer> stack = new Stack<>();
    
    for (int i = 0; i < n; i++) {
        if (!visited[i]) dfs1(i, graph, visited, stack);
    }
    
    // Step 2: Build transpose graph
    List<List<Integer>> transpose = new ArrayList<>();
    for (int i = 0; i < n; i++) transpose.add(new ArrayList<>());
    for (int u = 0; u < n; u++) {
        for (int v : graph.get(u)) transpose.get(v).add(u);
    }
    
    // Step 3: Process in stack order
    Arrays.fill(visited, false);
    List<List<Integer>> sccs = new ArrayList<>();
    
    while (!stack.isEmpty()) {
        int u = stack.pop();
        if (!visited[u]) {
            List<Integer> scc = new ArrayList<>();
            dfs2(u, transpose, visited, scc);
            sccs.add(scc);
        }
    }
    return sccs;
}
```

## **13. BIPARTITE GRAPH (2-COLORABLE)**

### 📖 **Theory**
A graph is **bipartite** if vertices can be split into two sets with **no edges within a set**. Equivalent to: **no odd-length cycles**. Check using BFS/DFS with 2-coloring.

### 🎨 **Visual Diagram**
```
BIPARTITE (Even cycle)      NOT BIPARTITE (Odd cycle)
   0 --- 1                      0 --- 1
   |     |                      |     |
   |     |                      3 --- 2
   3 --- 2                      
Colors: 0=red, 1=blue,         Color conflict at edge 2-3
2=red, 3=blue                  (both would be blue)
```

### 🔧 **Template Code**
```java
public boolean isBipartite(int n, List<List<Integer>> graph) {
    int[] color = new int[n];  // -1=uncolored, 0=red, 1=blue
    
    for (int i = 0; i < n; i++) {
        if (color[i] == -1) {
            if (!bfsCheck(i, graph, color)) return false;
        }
    }
    return true;
}

private boolean bfsCheck(int start, List<List<Integer>> graph, int[] color) {
    Queue<Integer> queue = new LinkedList<>();
    queue.offer(start);
    color[start] = 0;
    
    while (!queue.isEmpty()) {
        int u = queue.poll();
        for (int v : graph.get(u)) {
            if (color[v] == -1) {
                color[v] = color[u] ^ 1;
                queue.offer(v);
            } else if (color[v] == color[u]) {
                return false;
            }
        }
    }
    return true;
}
```

## **14. EULERIAN PATH/CIRCUIT**

### 📖 **Theory**
**Eulerian Circuit**: Visits every edge exactly once, returns to start.
**Eulerian Path**: Visits every edge exactly once, different start/end.

**Conditions:**
- **Undirected Graph**: 
  - Circuit: All vertices have even degree
  - Path: Exactly 0 or 2 vertices with odd degree
- **Directed Graph**:
  - Circuit: In-degree = out-degree for all vertices
  - Path: At most one vertex with out-in=1, one with in-out=1, rest equal

### 🎨 **Visual Diagram**
```
Eulerian Circuit (all edges once, return)
1 --- 2          Path: 1-2-4-3-1 (all edges visited)
|     |          1-2, 2-4, 4-3, 3-1
|     |
3 --- 4

Degree: all = 2 (even) → Circuit exists
```

### 🔧 **Template Code**
```java
// Hierholzer's Algorithm for Eulerian Path
public List<Integer> findEulerianPath(int n, List<List<Integer>> graph) {
    LinkedList<Integer> path = new LinkedList<>();
    
    // Find start node (odd degree or first non-isolated)
    int start = 0;
    for (int i = 0; i < n; i++) {
        if (graph.get(i).size() % 2 == 1) {
            start = i;
            break;
        }
    }
    
    // DFS with edge removal
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(start);
    
    while (!stack.isEmpty()) {
        int u = stack.peek();
        if (!graph.get(u).isEmpty()) {
            int v = graph.get(u).remove(0);
            graph.get(v).remove((Integer) u);  // remove reverse for undirected
            stack.push(v);
        } else {
            path.addFirst(stack.pop());
        }
    }
    return path;
}
```

# 📚 **PART 8: ADVANCED PATTERNS**

## **15. MULTI-SOURCE BFS**

### 📖 **Theory**
Start BFS from **multiple sources simultaneously**. Each source "expands" outward. Perfect for problems like: distance to nearest 0, rotting oranges, infection spread.

### 🎨 **Visual Diagram**
```
Grid: 0 1 1        Multi-source BFS:
      1 1 0        Sources: (0,0) and (1,2)
      0 1 1        
                    Layer 1: neighbors of sources
Layer 0: (0,0),(1,2) distance 0
Layer 1: (0,1),(1,1),(2,2) distance 1
Layer 2: (0,2),(2,1),(2,0) distance 2
```

### 🔧 **Template Code**
```java
public int[][] multiSourceBFS(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    int[][] dist = new int[m][n];
    Queue<int[]> queue = new LinkedList<>();
    
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            if (grid[i][j] == 0) {
                dist[i][j] = 0;
                queue.offer(new int[]{i, j});
            } else {
                dist[i][j] = Integer.MAX_VALUE;
            }
        }
    }
    
    int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};
    
    while (!queue.isEmpty()) {
        int[] cell = queue.poll();
        for (int[] d : dirs) {
            int ni = cell[0] + d[0], nj = cell[1] + d[1];
            if (ni >= 0 && ni < m && nj >= 0 && nj < n) {
                if (dist[ni][nj] > dist[cell[0]][cell[1]] + 1) {
                    dist[ni][nj] = dist[cell[0]][cell[1]] + 1;
                    queue.offer(new int[]{ni, nj});
                }
            }
        }
    }
    return dist;
}
```

## **16. GRID AS GRAPH**

### 📖 **Theory**
In grid problems, each cell is a **node**, adjacent cells are **edges**. Movement can be 4-directional (up/down/left/right) or 8-directional (including diagonals). Common patterns: islands, paths, flood fill.

### 🎨 **Visual Diagram**
```
Grid (4-directional):
(0,0) — (0,1) — (0,2)
  |       |       |
(1,0) — (1,1) — (1,2)
  |       |       |
(2,0) — (2,1) — (2,2)

Each cell connects to up to 4 neighbors.
(1,1) connects to (0,1), (2,1), (1,0), (1,2)
```

### 🔧 **Template Code**
```java
// Grid BFS template
int m = grid.length, n = grid[0].length;
int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};  // 4-directional

for (int i = 0; i < m; i++) {
    for (int j = 0; j < n; j++) {
        // Process cell (i,j)
        for (int[] d : dirs) {
            int ni = i + d[0], nj = j + d[1];
            if (ni >= 0 && ni < m && nj >= 0 && nj < n) {
                // neighbor exists
            }
        }
    }
}
```

# 📚 **PART 9: FLOW NETWORKS**

## **17. MAXIMUM FLOW (FORD-FULKERSON)**

### 📖 **Theory**
Maximum flow finds the maximum amount of flow from **source** to **sink** through a network with capacity constraints. **Ford-Fulkerson** repeatedly finds augmenting paths using DFS (Edmonds-Karp uses BFS for O(VE²) complexity).

**Key concepts**: Residual graph, augmenting path, min-cut = max-flow.

### 🎨 **Visual Diagram**
```
        (capacity)
    Source → A (10)
    Source → B (5)
    A → B (15)
    A → Sink (10)
    B → Sink (10)

Max Flow = 15
Paths: S→A→T (10), S→B→T (5)
```

### 🔧 **Template Code**
```java
// Edmonds-Karp (BFS-based Ford-Fulkerson)
public int maxFlow(int n, int[][] capacity, int source, int sink) {
    int[][] residual = new int[n][n];
    for (int i = 0; i < n; i++) {
        System.arraycopy(capacity[i], 0, residual[i], 0, n);
    }
    
    int maxFlow = 0;
    int[] parent = new int[n];
    
    while (bfs(residual, source, sink, parent)) {
        // Find bottleneck
        int bottleneck = Integer.MAX_VALUE;
        for (int v = sink; v != source; v = parent[v]) {
            int u = parent[v];
            bottleneck = Math.min(bottleneck, residual[u][v]);
        }
        
        // Update residual network
        for (int v = sink; v != source; v = parent[v]) {
            int u = parent[v];
            residual[u][v] -= bottleneck;
            residual[v][u] += bottleneck;
        }
        maxFlow += bottleneck;
    }
    return maxFlow;
}
```

| "Connected components" | DFS / BFS / Union-Find |
| "Strongly connected" | Kosaraju / Tarjan |
| "Bipartite / 2-coloring" | BFS / DFS |
| "Visit every edge once" | Eulerian Path |
| "Distance from multiple sources" | Multi-source BFS |
| "Grid / matrix" | Treat as graph (4-directional) |
| "Dynamic connectivity" | Union-Find |
| "Max flow / min cut" | Ford-Fulkerson |

## **Time Complexity Summary**

```
Algorithm          Time Complexity        Space
DFS/BFS            O(V + E)              O(V)
Dijkstra           O((V+E) log V)        O(V)
Bellman-Ford       O(V × E)              O(V)
Floyd-Warshall     O(V³)                 O(V²)
Kruskal            O(E log E)            O(V)
Prim               O((V+E) log V)        O(V)
Kosaraju           O(V + E)              O(V)
Topological Sort   O(V + E)              O(V)
Union-Find         O(α(V)) ≈ O(1)        O(V)
Ford-Fulkerson     O(E × max_flow)       O(V)
```
