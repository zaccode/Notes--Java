# **PART 1: UNION-FIND (DISJOINT SET UNION)**

## Why DSU Deserves Its Own Deep Dive

DSU is **not just one algorithm** — it's a **family of patterns**. Each pattern solves a different type of problem. If you don't learn the patterns, you'll struggle to recognize when to apply DSU.

## 📊 **DSU: Properties & Complexity**

| Property | Value |
|----------|-------|
| **Time Complexity (Find)** | O(α(n)) ≈ O(1) with path compression |
| **Time Complexity (Union)** | O(α(n)) ≈ O(1) with union by rank |
| **Space Complexity** | O(n) |
| **Works On** | Undirected Graphs only |
| **α(n)** | Inverse Ackermann function (≤ 4 for all practical n)  |

### When to Use DSU (The Signals)

## **PATTERN 1: Basic Connectivity & Component Counting**

### 📖 Theory
The **most fundamental DSU pattern**. You have a graph. You need to:
- Find how many connected components exist
- Check if two nodes are in the same component
- Merge components as edges are added

**Properties:**
- After all unions, each component has exactly **one root**
- Number of components = number of nodes with `parent[i] == i`
- Union operation reduces component count by 1 each time

### 🎨 Visual Diagram
```
Initial: 5 isolated nodes
[0] [1] [2] [3] [4]  → 5 components

Union(0,1):
[0-1] [2] [3] [4]    → 4 components

Union(2,3):
[0-1] [2-3] [4]      → 3 components

Union(1,2):
[0-1-2-3] [4]        → 2 components

Find(0) == Find(3)? Yes (same component)
```

### 🔧 Template Code
```java
class DSU {
    int[] parent;
    int[] rank;
    int components;
    
    public DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        components = n;
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    
    public int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);  // Path compression
        }
        return parent[x];
    }
    
    public boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false;
        
        // Union by rank
        if (rank[px] < rank[py]) {
            parent[px] = py;
        } else if (rank[px] > rank[py]) {
            parent[py] = px;
        } else {
            parent[py] = px;
            rank[px]++;
        }
        components--;
        return true;
    }
    
    public boolean connected(int x, int y) {
        return find(x) == find(y);
    }
    
    public int countComponents() {
        return components;
    }
}
```

## **PATTERN 2: Cycle Detection in Undirected Graph**

### 📖 Theory
In an **undirected graph**, adding an edge creates a cycle **if and only if** its two endpoints are already in the same connected component.

**Properties:**
- Process edges one by one
- Before union, check if `find(u) == find(v)`
- If yes → this edge creates a cycle
- This is how Kruskal's MST algorithm detects cycles 

### 🎨 Visual Diagram
```
Edges processed in order:

1. Add edge (0-1): 0 and 1 in different components → union ✅
   Components: {0,1}, {2}, {3}

2. Add edge (1-2): 1 in {0,1}, 2 in {2} → different → union ✅
   Components: {0,1,2}, {3}

3. Add edge (0-2): 0 and 2 in SAME component {0,1,2} → CYCLE! ❌
   Edge (0-2) is redundant
```

### 🔧 Template Code
```java
public int[] findRedundantConnection(int[][] edges, int n) {
    DSU dsu = new DSU(n);
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1];
        if (dsu.find(u) == dsu.find(v)) {
            return edge;  // This edge creates a cycle
        }
        dsu.union(u, v);
    }
    return new int[0];
}
```

## **PATTERN 3: Offline Queries (Sort + Process Incrementally)**

### 📖 Theory
This is where DSU **truly shines**. When you have queries asking "is there a path with all edges weight < limit?", you can't answer online efficiently. Instead:

1. **Sort edges by weight**
2. **Sort queries by limit**
3. **Process queries in increasing order** - add edges gradually
4. **Answer query** using DSU connectivity check

**Properties:**
- Time Complexity: O(E log E + Q log Q + (E+Q) × α(n))
- Much faster than answering each query independently 

### 🎨 Visual Diagram
```
Edges: (0-1:5), (1-2:3), (2-3:7), (0-3:9)
Queries: 
  Q1: limit=4 → can use edges with weight <4: only (1-2:3)
  Q2: limit=6 → can use edges weight <6: (1-2:3), (0-1:5)
  Q3: limit=10 → can use all edges

Process:
  Sort queries by limit: Q1(4), Q2(6), Q3(10)
  Pointer i=0 on edges (sorted by weight)
  
  For Q1: add edges weight<4 → add (1-2)
  For Q2: add edges weight<6 → add (0-1)
  For Q3: add remaining edges → add (2-3), (0-3)
```

### 🔧 Template Code
```java
public boolean[] offlineQueries(int n, int[][] edges, int[][] queries) {
    // queries: [u, v, limit]
    Arrays.sort(edges, (a,b) -> a[2] - b[2]);  // sort edges by weight
    
    // Prepare queries with original index
    int q = queries.length;
    int[][] queriesWithIdx = new int[q][4];
    for (int i = 0; i < q; i++) {
        queriesWithIdx[i] = new int[]{queries[i][0], queries[i][1], queries[i][2], i};
    }
    Arrays.sort(queriesWithIdx, (a,b) -> a[2] - b[2]);  // sort by limit
    
    DSU dsu = new DSU(n);
    boolean[] ans = new boolean[q];
    int edgePtr = 0;
    
    for (int[] query : queriesWithIdx) {
        int u = query[0], v = query[1], limit = query[2], idx = query[3];
        
        // Add all edges with weight < limit
        while (edgePtr < edges.length && edges[edgePtr][2] < limit) {
            dsu.union(edges[edgePtr][0], edges[edgePtr][1]);
            edgePtr++;
        }
        
        ans[idx] = dsu.connected(u, v);
    }
    return ans;
}
```

## **PATTERN 4: String/Email Grouping (Map-Based DSU)**

### 📖 Theory
Nodes are **not always integers**. When dealing with strings, emails, or objects:
- **Map each unique value to an index** (0, 1, 2, ...)
- Use DSU on indices
- Track which indices belong together

**Properties:**
- Requires a `HashMap<String, Integer>` for mapping
- Union entities that share common attributes 

### 🎨 Visual Diagram
```
Accounts: [
  ["John", "j1@mail.com", "j2@mail.com"],
  ["John", "j2@mail.com", "j3@mail.com"],
  ["Mary", "m1@mail.com"]
]

Step 1: Map emails to indices
  "j1@mail.com" → 0
  "j2@mail.com" → 1
  "j3@mail.com" → 2
  "m1@mail.com" → 3

Step 2: Union emails within same account
  Account 0: union(0,1)
  Account 1: union(1,2) → now 0,1,2 all connected
  Account 2: 3 alone

Result: Component 1: {0,1,2} (John's emails)
        Component 2: {3} (Mary's email)
```

### 🔧 Template Code
```java
public List<List<String>> accountsMerge(List<List<String>> accounts) {
    DSU dsu = new DSU(accounts.size());  // One node per account initially
    Map<String, Integer> emailToAccountId = new HashMap<>();
    
    // First pass: Union accounts that share emails
    for (int i = 0; i < accounts.size(); i++) {
        List<String> account = accounts.get(i);
        for (int j = 1; j < account.size(); j++) {
            String email = account.get(j);
            if (emailToAccountId.containsKey(email)) {
                dsu.union(i, emailToAccountId.get(email));
            } else {
                emailToAccountId.put(email, i);
            }
        }
    }
    
    // Second pass: Group emails by root account
    Map<Integer, List<String>> rootToEmails = new HashMap<>();
    for (Map.Entry<String, Integer> entry : emailToAccountId.entrySet()) {
        int root = dsu.find(entry.getValue());
        rootToEmails.computeIfAbsent(root, k -> new ArrayList<>()).add(entry.getKey());
    }
    
    // Format output
    List<List<String>> result = new ArrayList<>();
    for (Map.Entry<Integer, List<String>> entry : rootToEmails.entrySet()) {
        List<String> emails = entry.getValue();
        Collections.sort(emails);
        List<String> merged = new ArrayList<>();
        merged.add(accounts.get(entry.getKey()).get(0));  // name
        merged.addAll(emails);
        result.add(merged);
    }
    return result;
}
```

## **PATTERN 5: Lexicographical/String Ordering After Swaps**

### 📖 Theory
You have positions that can be swapped freely. The positions that are **connected** (directly or indirectly) can be rearranged arbitrarily.

**Properties:**
- Union positions that are connected by swap operations
- For each component, collect characters at those positions
- Sort characters in descending order
- Place back in ascending order of positions 

### 🎨 Visual Diagram
```
String: "dcab"
Swaps: [0,3], [1,2]

Step 1: Build connections
  Union(0,3)
  Union(1,2)
  
Step 2: Components
  Component A: positions {0,3} → characters {'d','b'}
  Component B: positions {1,2} → characters {'c','a'}

Step 3: Sort each component's characters
  Component A sorted: {'b','d'}
  Component B sorted: {'a','c'}

Step 4: Place back (positions sorted ascending)
  pos0 (A) → 'b'
  pos1 (B) → 'a'
  pos2 (B) → 'c'
  pos3 (A) → 'd'
  
Result: "bacd"
```

### 🔧 Template Code
```java
public String smallestStringWithSwaps(String s, List<List<Integer>> pairs) {
    int n = s.length();
    DSU dsu = new DSU(n);
    
    // Union all positions that can be swapped
    for (List<Integer> pair : pairs) {
        dsu.union(pair.get(0), pair.get(1));
    }
    
    // Group indices by root
    Map<Integer, List<Integer>> rootToIndices = new HashMap<>();
    for (int i = 0; i < n; i++) {
        int root = dsu.find(i);
        rootToIndices.computeIfAbsent(root, k -> new ArrayList<>()).add(i);
    }
    
    // Build result
    char[] result = new char[n];
    for (Map.Entry<Integer, List<Integer>> entry : rootToIndices.entrySet()) {
        List<Integer> indices = entry.getValue();
        
        // Get characters at these indices
        List<Character> chars = new ArrayList<>();
        for (int idx : indices) {
            chars.add(s.charAt(idx));
        }
        
        // Sort characters ascending
        Collections.sort(chars);
        // Sort indices ascending
        Collections.sort(indices);
        
        // Place smallest char at smallest index
        for (int i = 0; i < indices.size(); i++) {
            result[indices.get(i)] = chars.get(i);
        }
    }
    return new String(result);
}
```

## **PATTERN 6: Two-Player/Two-Entity Connectivity**

### 📖 Theory
Problems with **two entities** (Alice and Bob, two networks, etc.). You maintain **two separate DSU structures** or track connectivity for both simultaneously.

**Properties:**
- Process shared edges first (they benefit both)
- Then process entity-specific edges
- Track component counts for each entity separately 

### 🎨 Visual Diagram
```
Edges:
  Type 1: Alice-only
  Type 2: Bob-only  
  Type 3: Both can use

Strategy:
  1. Use Type 3 edges first for BOTH DSUs
  2. Then use Type 1 for Alice's DSU
  3. Then use Type 2 for Bob's DSU
  4. Count unused edges = total - used
```

### 🔧 Template Code
```java
public int maxNumEdgesToRemove(int n, int[][] edges) {
    DSU alice = new DSU(n);
    DSU bob = new DSU(n);
    int edgesUsed = 0;
    
    // First: Process type 3 edges (both can use)
    for (int[] edge : edges) {
        if (edge[0] == 3) {
            if (alice.union(edge[1]-1, edge[2]-1) | bob.union(edge[1]-1, edge[2]-1)) {
                edgesUsed++;
            }
        }
    }
    
    // Second: Process type 1 edges (Alice only)
    for (int[] edge : edges) {
        if (edge[0] == 1) {
            if (alice.union(edge[1]-1, edge[2]-1)) {
                edgesUsed++;
            }
        }
    }
    
    // Third: Process type 2 edges (Bob only)
    for (int[] edge : edges) {
        if (edge[0] == 2) {
            if (bob.union(edge[1]-1, edge[2]-1)) {
                edgesUsed++;
            }
        }
    }
    
    // Check if both are fully connected
    if (alice.countComponents() != 1 || bob.countComponents() != 1) {
        return -1;
    }
    
    return edges.length - edgesUsed;
}
```

## **PATTERN 7: Prime Factor / GCD-Based Union**

### 📖 Theory
Elements are connected if they **share a common factor > 1**. Instead of checking all pairs (O(n²)), union each number with its **prime factors**.

**Properties:**
- For each number, find its prime factors
- Union the number with each factor (treat factors as nodes)
- After processing, numbers with shared factors will be in same component 

### 🎨 Visual Diagram
```
Numbers: [2, 3, 6, 7, 14]

Step 1: Map numbers to indices
  2→0, 3→1, 6→2, 7→3, 14→4

Step 2: For each number, union with prime factors
  2: factors [2] → union(0, 2)
  3: factors [3] → union(1, 3)
  6: factors [2,3] → union(2,2), union(2,3)
  7: factors [7] → union(3,7)
  14: factors [2,7] → union(4,2), union(4,7)

Result: 
  Component A: {2,3,6,7,14} (all connected via 2 and 7)
  Wait, 3 is connected? Yes via 6 (3 and 6 share factor 3)
  Actually 3 connects to 6, 6 connects to 2, 2 connects to 14, 14 connects to 7
  So ALL numbers are connected!
```

### 🔧 Template Code
```java
public int largestComponentSize(int[] nums) {
    int n = nums.length;
    DSU dsu = new DSU(n);
    Map<Integer, List<Integer>> factorToNumbers = new HashMap<>();
    
    // For each number, find its factors
    for (int i = 0; i < n; i++) {
        int num = nums[i];
        int temp = num;
        for (int f = 2; f * f <= temp; f++) {
            if (temp % f == 0) {
                while (temp % f == 0) temp /= f;
                factorToNumbers.computeIfAbsent(f, k -> new ArrayList<>()).add(i);
            }
        }
        if (temp > 1) {
            factorToNumbers.computeIfAbsent(temp, k -> new ArrayList<>()).add(i);
        }
    }
    
    // Union numbers that share factors
    for (List<Integer> numberIndices : factorToNumbers.values()) {
        int first = numberIndices.get(0);
        for (int i = 1; i < numberIndices.size(); i++) {
            dsu.union(first, numberIndices.get(i));
        }
    }
    
    // Count largest component size
    int[] size = new int[n];
    int maxSize = 0;
    for (int i = 0; i < n; i++) {
        int root = dsu.find(i);
        size[root]++;
        maxSize = Math.max(maxSize, size[root]);
    }
    return maxSize;
}
```

## **PATTERN 8: Equality/Inequality Equations (Satisfiability)**

### 📖 Theory
Given equations like `"a==b"`, `"c!=d"`, determine if all can be satisfied simultaneously.

**Properties:**
- **First pass**: Union all variables connected by `==` equations
- **Second pass**: Check all `!=` equations — if both variables in same component → contradiction 

### 🎨 Visual Diagram
```
Equations: 
  a==b, b==c, c!=d, d==e

Step 1: Process == equations
  Union(a,b), Union(b,c) → {a,b,c} in same component
  Union(d,e) → {d,e} in same component

Step 2: Process != equations
  Check c!=d: c in {a,b,c}, d in {d,e} → Different components ✅ OK

If we had a!=b:
  a and b in same component → Contradiction! ❌
```

### 🔧 Template Code
```java
public boolean equationsPossible(String[] equations) {
    DSU dsu = new DSU(26);  // 26 lowercase letters
    
    // First pass: Union all '==' equations
    for (String eq : equations) {
        if (eq.charAt(1) == '=') {
            int x = eq.charAt(0) - 'a';
            int y = eq.charAt(3) - 'a';
            dsu.union(x, y);
        }
    }
    
    // Second pass: Check all '!=' equations
    for (String eq : equations) {
        if (eq.charAt(1) == '!') {
            int x = eq.charAt(0) - 'a';
            int y = eq.charAt(3) - 'a';
            if (dsu.find(x) == dsu.find(y)) {
                return false;  // Contradiction
            }
        }
    }
    return true;
}
```

## **PATTERN 9: Minimum Time to Connect / Binary Search + DSU**

### 📖 Theory
Problems asking "minimum maximum effort" or "earliest time when nodes become connected" — use **binary search on answer** + DSU to check feasibility.

**Properties:**
- Binary search on the threshold (time, effort, distance)
- For a given threshold, union all edges with weight ≤ threshold
- Check if source and target are connected 

### 🎨 Visual Diagram
```
Find minimum effort path from top-left to bottom-right:

Grid:
[0, 2, 5]
[3, 8, 1]
[4, 6, 7]

Binary Search on effort:
  low=0, high=8
  mid=4: Can we reach with max effort ≤4?
    Union edges with diff ≤4
    Check if (0,0) and (2,2) connected? No → low=5
  mid=6: Can we reach with max effort ≤6?
    Union edges with diff ≤6
    Check if connected? Yes → high=6
  Result: 6
```

### 🔧 Template Code
```java
public int minimumEffortPath(int[][] heights) {
    int m = heights.length, n = heights[0].length;
    int left = 0, right = 1000000;
    int ans = right;
    
    while (left <= right) {
        int mid = left + (right - left) / 2;
        
        if (canReach(heights, mid)) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    return ans;
}

private boolean canReach(int[][] heights, int maxDiff) {
    int m = heights.length, n = heights[0].length;
    DSU dsu = new DSU(m * n);
    int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};
    
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            int idx = i * n + j;
            for (int[] d : dirs) {
                int ni = i + d[0], nj = j + d[1];
                if (ni >= 0 && ni < m && nj >= 0 && nj < n) {
                    int nidx = ni * n + nj;
                    if (Math.abs(heights[i][j] - heights[ni][nj]) <= maxDiff) {
                        dsu.union(idx, nidx);
                    }
                }
            }
        }
    }
    
    return dsu.connected(0, m * n - 1);
}
```

## **PATTERN 10: Reverse Thinking / Time-Travel DSU**

### 📖 Theory
Problems that ask "what happens if we remove edges" — instead of removing, **add edges in reverse order**.

**Properties:**
- Start from the final state (after all removals)
- Process operations backwards
- When we "remove" in original, we "add" in reverse 

### 🎨 Visual Diagram
```
Original: Remove edges in order: e1, e2, e3
          0---1---2
          |       |
          3-------4

Forward thinking (hard): 
  Start with graph, remove e1, track connectivity changes

Reverse thinking (easy):
  Start with graph MINUS e1,e2,e3
  Add e3, then e2, then e1
  Track when components merge
```

### 🔧 Template Code
```java
public int[] findRedundantConnection(int[][] edges) {
    int n = edges.length;
    DSU dsu = new DSU(n + 1);
    
    for (int[] edge : edges) {
        if (!dsu.union(edge[0], edge[1])) {
            return edge;  // This edge creates a cycle
        }
    }
    return new int[0];
}

// For removal problems:
public List<Boolean> areConnectedAfterRemovals(int n, int[][] edges, int[][] queries) {
    // Process queries in reverse: removals become additions
    DSU dsu = new DSU(n);
    Set<String> removed = new HashSet<>();
    
    // Mark edges that will be removed
    for (int[] q : queries) {
        removed.add(q[0] + "," + q[1]);
    }
    
    // Add edges that are never removed
    for (int[] e : edges) {
        if (!removed.contains(e[0] + "," + e[1])) {
            dsu.union(e[0], e[1]);
        }
    }
    
    // Process queries in reverse
    List<Boolean> ans = new ArrayList<>();
    for (int i = queries.length - 1; i >= 0; i--) {
        ans.add(dsu.connected(queries[i][0], queries[i][1]));
        dsu.union(queries[i][0], queries[i][1]);  // Add edge back
    }
    Collections.reverse(ans);
    return ans;
}
```

## **PATTERN 1: Basic Dijkstra (Single Source Shortest Path)**

### 📖 Theory
The **fundamental Dijkstra pattern**. Start from source node, use priority queue to always expand the node with smallest known distance. For each neighbor, if new distance is smaller, update and push to PQ.

**Properties:**
- Once a node is popped from PQ, its distance is finalized (greedy choice property)
- Works only with non-negative weights
- If graph is unweighted, BFS is faster (O(V+E) vs O((V+E)log V))

### 🎨 Visual Diagram
```
Graph:     0 --4--> 1
           |         |
           2         1
           |         |
           2 --3--> 3

Dijkstra from node 0:

Initial: dist = [0, ∞, ∞, ∞], PQ = [(0,0)]

Step 1: Pop (0,0)
  Neighbors: 1 (4), 2 (2)
  dist[1] = 4, dist[2] = 2
  PQ = [(2,2), (4,1)]

Step 2: Pop (2,2)
  Neighbors: 3 (3)
  dist[3] = 5
  PQ = [(4,1), (5,3)]

Step 3: Pop (4,1)
  Neighbors: 3 (1)
  dist[3] = min(5, 4+1=5) → 5
  PQ = [(5,3)]

Result: dist = [0, 4, 2, 5]
```

### 🔧 Template Code
```java
public int[] dijkstra(int n, List<int[]>[] graph, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // Priority queue: [distance, node]
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0] - b[0]);
    pq.offer(new int[]{0, src});
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        
        // Skip stale entries
        if (d > dist[u]) continue;
        
        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    return dist;
}
```

## **PATTERN 2: Multiple Sources / Multi-Source Dijkstra**

### 📖 Theory
When you have **multiple starting points** and need the shortest distance to all nodes from **any source**. Initialize PQ with ALL sources at distance 0.

**Properties:**
- Same as single-source, but PQ starts with all sources
- Distances represent distance to nearest source
- Perfect for "nearest hospital", "nearest fire station" problems

### 🎨 Visual Diagram
```
Grid with sources (0 = source, ∞ = empty):
[0] [∞] [∞]
[∞] [0] [∞]
[∞] [∞] [∞]

Multi-source Dijkstra:
Initialize PQ with both (0,0,0) and (0,1,1)
Propagate outward like BFS but with weights

Result distances:
[0] [1] [2]
[1] [0] [1]
[2] [1] [2]
```

### 🔧 Template Code
```java
public int[] multiSourceDijkstra(int n, List<int[]>[] graph, int[] sources) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0] - b[0]);
    
    // Add all sources with distance 0
    for (int src : sources) {
        dist[src] = 0;
        pq.offer(new int[]{0, src});
    }
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (d > dist[u]) continue;
        
        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    return dist;
}
```

## **PATTERN 3: Minimize Maximum Edge Weight (Minimax Path)**

### 📖 Theory
Find a path from source to destination that **minimizes the maximum edge weight** along the path. Use **modified Dijkstra** where the "distance" stored is the maximum edge weight so far.

**Properties:**
- Relaxation: `newMax = max(currentMax, edgeWeight)`
- If `newMax < dist[v]`, update
- Can also be solved with Binary Search + BFS/DSU

### 🎨 Visual Diagram
```
Path options from 0 to 3:

Path 1: 0→1 (5) → 3 (2) → max = max(5,2) = 5
Path 2: 0→2 (3) → 3 (4) → max = max(3,4) = 4
Path 3: 0→1 (5) → 2 (1) → 3 (4) → max = max(5,1,4) = 5

Minimax path: Path 2 with max edge = 4
```

### 🔧 Template Code
```java
public int minimaxPath(int n, List<int[]>[] graph, int src, int dest) {
    int[] maxEdge = new int[n];
    Arrays.fill(maxEdge, Integer.MAX_VALUE);
    maxEdge[src] = 0;
    
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0] - b[0]);
    pq.offer(new int[]{0, src});
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int maxSoFar = curr[0], u = curr[1];
        
        if (u == dest) return maxSoFar;
        if (maxSoFar > maxEdge[u]) continue;
        
        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            int newMax = Math.max(maxSoFar, w);
            if (newMax < maxEdge[v]) {
                maxEdge[v] = newMax;
                pq.offer(new int[]{newMax, v});
            }
        }
    }
    return -1;
}
```

## **PATTERN 4: K Stops / Limited Hops (Modified Dijkstra)**

### 📖 Theory
Find shortest path with **constraint on number of edges/hops/stops**. Use `dist[node][k]` where k is stops used. Or use BFS + relaxation with stop count.

**Properties:**
- Bellman-Ford is more natural for K stops, but Dijkstra works with `(node, stops)` state
- Stop constraint makes graph "layered" by number of hops used

### 🎨 Visual Diagram
```
Flights: 0→1 (100), 0→2 (500), 1→2 (100), 1→3 (500), 2→3 (100)
K=1 stop (max 2 edges)

From 0 to 3 with K=1:
  0→1→3: cost = 100 + 500 = 600
  0→2→3: cost = 500 + 100 = 600
  0→1→2→3: NOT allowed (2 stops, K=1)
  
Dijkstra with state (node, stops):
  Start: (0,0) cost=0
  (0,0) → (1,1) cost=100, (2,1) cost=500
  (1,1) → (3,2) cost=600 (but stops=2 > K? No, K=1 means stops≤1)
  Wait, stops=2 means used 2 flights = 1 stop? Let's clarify:
    Stops = intermediate airports = edges - 1
    K=1 stop means max 2 edges
    (node, edgesUsed) is clearer
```

### 🔧 Template Code
```java
public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
    List<int[]>[] graph = new ArrayList[n];
    for (int i = 0; i < n; i++) graph[i] = new ArrayList<>();
    for (int[] f : flights) graph[f[0]].add(new int[]{f[1], f[2]});
    
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // Priority queue: [cost, node, stops]
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0] - b[0]);
    pq.offer(new int[]{0, src, 0});
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int cost = curr[0], u = curr[1], stops = curr[2];
        
        if (u == dst) return cost;
        if (stops > k) continue;
        
        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            if (cost + w < dist[v]) {
                dist[v] = cost + w;
                pq.offer(new int[]{cost + w, v, stops + 1});
            }
        }
    }
    return -1;
}
```

## **PATTERN 5: Dijkstra on Grid with Weights**

### 📖 Theory
When moving in a grid where each cell has a cost, or moving in 4/8 directions has different weights. Treat each cell as a node, neighbors are adjacent cells.

**Properties:**
- Grid becomes a graph with V = rows × cols
- Each cell connects to up to 4 neighbors
- Weight can be cell value or movement cost

### 🎨 Visual Diagram
```
Grid with cell costs:
[1, 2, 3]
[4, 5, 6]
[7, 8, 9]

From (0,0) to (2,2):
Path: (0,0)[1] → (0,1)[2] → (1,1)[5] → (2,2)[9]
Total cost = 1+2+5+9 = 17

Dijkstra on grid:
  dist[0][0] = 1
  From (0,0): (0,1) cost=1+2=3, (1,0) cost=1+4=5
  ...
```

### 🔧 Template Code
```java
public int minCostPath(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    int[][] dist = new int[m][n];
    for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
    dist[0][0] = grid[0][0];
    
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[2] - b[2]);
    pq.offer(new int[]{0, 0, grid[0][0]});
    
    int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int i = curr[0], j = curr[1], cost = curr[2];
        
        if (i == m-1 && j == n-1) return cost;
        if (cost > dist[i][j]) continue;
        
        for (int[] d : dirs) {
            int ni = i + d[0], nj = j + d[1];
            if (ni >= 0 && ni < m && nj >= 0 && nj < n) {
                int newCost = cost + grid[ni][nj];
                if (newCost < dist[ni][nj]) {
                    dist[ni][nj] = newCost;
                    pq.offer(new int[]{ni, nj, newCost});
                }
            }
        }
    }
    return -1;
}
```

## **PATTERN 6: Dijkstra with State (Bitmask + Position)**

### 📖 Theory
When the graph has **state** (keys collected, visited nodes, etc.). State is represented as bitmask. Node becomes `(position, state)`. Transitions modify state.

**Properties:**
- Total states = positions × 2^k where k = number of keys/items
- Dijkstra works on state graph
- Used in "shortest path to collect all keys" problems

### 🎨 Visual Diagram
```
Grid with keys (a,b) and doors (A,B):
Start at (0,0) with mask=00

State space:
(0,0,00) → pick key 'a' → (0,0,01)
(0,0,01) → can open door 'A'
(0,0,01) → pick key 'b' → (0,0,11)

Each cell has up to 2^k states
```

### 🔧 Template Code
```java
public int shortestPathToGetAllKeys(String[] grid) {
    int m = grid.length, n = grid[0].length();
    int totalKeys = 0;
    int startX = 0, startY = 0;
    
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            char c = grid[i].charAt(j);
            if (c == '@') { startX = i; startY = j; }
            if (c >= 'a' && c <= 'f') totalKeys++;
        }
    }
    
    int[][][] dist = new int[m][n][1 << totalKeys];
    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++)
            Arrays.fill(dist[i][j], Integer.MAX_VALUE);
    
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[3] - b[3]);
    dist[startX][startY][0] = 0;
    pq.offer(new int[]{startX, startY, 0, 0}); // x,y,mask,steps
    
    int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int i = curr[0], j = curr[1], mask = curr[2], steps = curr[3];
        
        if (mask == (1 << totalKeys) - 1) return steps;
        
        for (int[] d : dirs) {
            int ni = i + d[0], nj = j + d[1];
            if (ni < 0 || ni >= m || nj < 0 || nj >= n) continue;
            
            char cell = grid[ni].charAt(nj);
            if (cell == '#') continue;
            
            int newMask = mask;
            if (cell >= 'a' && cell <= 'f') {
                newMask |= (1 << (cell - 'a'));
            }
            if (cell >= 'A' && cell <= 'F') {
                if ((newMask & (1 << (cell - 'A'))) == 0) continue;
            }
            
            if (steps + 1 < dist[ni][nj][newMask]) {
                dist[ni][nj][newMask] = steps + 1;
                pq.offer(new int[]{ni, nj, newMask, steps + 1});
            }
        }
    }
    return -1;
}
```

## **PATTERN 7: Dijkstra + Path Reconstruction**

### 📖 Theory
Not only find shortest distance, but also **reconstruct the actual path**. Store `parent[node]` for each node. After Dijkstra finishes, backtrack from destination to source.

**Properties:**
- Update parent whenever distance improves
- Path is reconstructed in reverse order
- Works only when there's a unique/single shortest path

### 🎨 Visual Diagram
```
Graph: 0--4--1--2--3
       |        |
       5--------

Parent array updates:
  dist[1] = 4, parent[1] = 0
  dist[2] = 6, parent[2] = 1
  dist[3] = 8, parent[3] = 2

Reconstruct path 0→3:
  start at 3, parent[3]=2
  parent[2]=1, parent[1]=0
  Reverse: 0→1→2→3
```

### 🔧 Template Code
```java
public int[] dijkstraWithPath(int n, List<int[]>[] graph, int src, int dest) {
    int[] dist = new int[n];
    int[] parent = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    Arrays.fill(parent, -1);
    dist[src] = 0;
    
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0] - b[0]);
    pq.offer(new int[]{0, src});
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (d > dist[u]) continue;
        
        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                parent[v] = u;  // Store parent
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    
    // Reconstruct path
    List<Integer> path = new ArrayList<>();
    for (int v = dest; v != -1; v = parent[v]) {
        path.add(v);
    }
    Collections.reverse(path);
    return path.stream().mapToInt(i->i).toArray();
}
```

## **PATTERN 1: Basic Bellman-Ford (Single Source with Negative Weights)**

### 📖 Theory
Relax all edges **V-1 times**. After V-1 iterations, shortest paths are found (if no negative cycles). Why V-1? Longest simple path has V-1 edges.

**Properties:**
- Can handle negative weights
- Slower than Dijkstra but more general
- If graph has no negative cycles, V-1 iterations suffice

### 🎨 Visual Diagram
```
Graph: 0 → 1 (4), 0 → 2 (3), 2 → 1 (-2)

Iteration 1:
  dist[0] = 0
  Relax 0→1: dist[1] = min(∞, 0+4) = 4
  Relax 0→2: dist[2] = min(∞, 0+3) = 3
  Relax 2→1: dist[1] = min(4, 3+(-2)=1) = 1

Iteration 2:
  Relax 2→1: dist[1] = min(1, 3+(-2)=1) = 1

Result: dist[1] = 1 (found shorter path via 0→2→1)
```

### 🔧 Template Code
```java
public int[] bellmanFord(int n, int[][] edges, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // Relax V-1 times
    for (int i = 0; i < n - 1; i++) {
        for (int[] edge : edges) {
            int u = edge[0], v = edge[1], w = edge[2];
            if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
            }
        }
    }
    
    // Check for negative cycles
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1], w = edge[2];
        if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
            return null;  // Negative cycle exists
        }
    }
    return dist;
}
```

## **PATTERN 2: Negative Cycle Detection**

### 📖 Theory
After V-1 relaxations, perform **one more relaxation**. If any distance improves → negative cycle exists. A negative cycle means shortest path is undefined (-∞).

**Properties:**
- Negative cycle can be reached from source
- All nodes reachable from cycle have -∞ distance
- Used in arbitrage detection

### 🎨 Visual Diagram
```
Graph with negative cycle:
0 → 1 (1)
1 → 2 (1)
2 → 0 (-3)

Cycle: 0→1→2→0 sum = 1+1+(-3) = -1

Bellman-Ford after V-1=3 iterations:
  dist[0] = 0
  dist[1] = 1
  dist[2] = 2

4th iteration (check for negative cycle):
  Relax 2→0: dist[0] = min(0, 2+(-3)=-1) → IMPROVEMENT!
  Negative cycle detected!
```

### 🔧 Template Code
```java
public boolean hasNegativeCycle(int n, int[][] edges, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // Relax V times (instead of V-1)
    for (int i = 0; i < n; i++) {
        boolean updated = false;
        for (int[] edge : edges) {
            int u = edge[0], v = edge[1], w = edge[2];
            if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                updated = true;
                if (i == n - 1) return true;  // Negative cycle on Vth iteration
            }
        }
        if (!updated) break;
    }
    return false;
}
```

## **PATTERN 3: K Stops / Limited Edges (Natural Bellman-Ford)**

### 📖 Theory
Bellman-Ford is **naturally suited** for "shortest path with at most K edges". Just run **K+1 iterations** instead of V-1. Each iteration adds at most one edge to paths.

**Properties:**
- No priority queue needed
- Natural stop count constraint
- Each iteration = paths with i edges

### 🎨 Visual Diagram
```
K=1 (max 2 edges):
Initial: dist = [0, ∞, ∞, ∞]

Iteration 1 (1 edge paths):
  dist[1] = 100, dist[2] = 500

Iteration 2 (2 edge paths):
  dist[3] = min(∞, dist[1]+500=600, dist[2]+100=600) = 600

Iteration 3 (3 edge paths - NOT allowed for K=1):
  dist[3] = min(600, dist[?]) → but we stop at K+1=2 iterations
```

### 🔧 Template Code
```java
public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // Run K+1 iterations (K stops = K+1 edges)
    for (int i = 0; i <= k; i++) {
        int[] temp = Arrays.copyOf(dist, n);
        for (int[] flight : flights) {
            int u = flight[0], v = flight[1], w = flight[2];
            if (dist[u] != Integer.MAX_VALUE && dist[u] + w < temp[v]) {
                temp[v] = dist[u] + w;
            }
        }
        dist = temp;
    }
    
    return dist[dst] == Integer.MAX_VALUE ? -1 : dist[dst];
}
```

## **PATTERN 4: Currency Arbitrage / Exchange Rates**

### 📖 Theory
Currency exchange rates can be modeled as a graph. Arbitrage exists if product of exchange rates in a cycle > 1. Take **negative log** to convert to negative cycle detection.

**Properties:**
- Convert rates to weights: `w = -log(rate)`
- Arbitrage = negative cycle
- Bellman-Ford detects it

### 🎨 Visual Diagram
```
Currencies: USD → EUR (0.9), EUR → GBP (0.8), GBP → USD (1.4)

Product: 0.9 × 0.8 × 1.4 = 1.008 > 1 → Arbitrage!

Convert to weights: w = -log(rate)
  USD→EUR: -log(0.9) = 0.105
  EUR→GBP: -log(0.8) = 0.223
  GBP→USD: -log(1.4) = -0.336

Sum of cycle = 0.105 + 0.223 + (-0.336) = -0.008 < 0 → Negative cycle!
```

### 🔧 Template Code
```java
public boolean hasArbitrage(int n, double[][] exchangeRates) {
    // Convert to log weights
    double[][] graph = new double[n][n];
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            if (i != j && exchangeRates[i][j] > 0) {
                graph[i][j] = -Math.log(exchangeRates[i][j]);
            }
        }
    }
    
    // Bellman-Ford to detect negative cycle
    double[] dist = new double[n];
    Arrays.fill(dist, Double.POSITIVE_INFINITY);
    dist[0] = 0;
    
    for (int i = 0; i < n - 1; i++) {
        for (int u = 0; u < n; u++) {
            for (int v = 0; v < n; v++) {
                if (graph[u][v] > 0 && dist[u] + graph[u][v] < dist[v]) {
                    dist[v] = dist[u] + graph[u][v];
                }
            }
        }
    }
    
    // Check for negative cycle
    for (int u = 0; u < n; u++) {
        for (int v = 0; v < n; v++) {
            if (graph[u][v] > 0 && dist[u] + graph[u][v] < dist[v]) {
                return true;  // Arbitrage exists
            }
        }
    }
    return false;
}
```

## **PATTERN 5: Shortest Path with Constraints**

### 📖 Theory
When there are constraints like "path must have at most X red edges" or "must pass through certain nodes", use Bellman-Ford with **state** (node, constraint_value).

**Properties:**
- State space = nodes × (constraint_range)
- Bellman-Ford relaxes over state graph
- Similar to Dijkstra with state but handles negative weights

### 🔧 Template Code
```java
public int shortestPathWithConstraints(int n, int[][] edges, int src, int dest, int maxRedEdges) {
    // dist[node][redUsed] = min distance
    int[][] dist = new int[n][maxRedEdges + 1];
    for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
    dist[src][0] = 0;
    
    for (int i = 0; i < n - 1; i++) {
        for (int[] edge : edges) {
            int u = edge[0], v = edge[1], w = edge[2];
            boolean isRed = edge[3] == 1;
            
            for (int red = 0; red <= maxRedEdges; red++) {
                if (dist[u][red] == Integer.MAX_VALUE) continue;
                
                int newRed = red + (isRed ? 1 : 0);
                if (newRed <= maxRedEdges) {
                    if (dist[u][red] + w < dist[v][newRed]) {
                        dist[v][newRed] = dist[u][red] + w;
                    }
                }
            }
        }
    }
    
    int ans = Integer.MAX_VALUE;
    for (int red = 0; red <= maxRedEdges; red++) {
        ans = Math.min(ans, dist[dest][red]);
    }
    return ans == Integer.MAX_VALUE ? -1 : ans;
}
```

## **PATTERN 1: Basic MST (Kruskal + Prim)**

### 📖 Theory
**Kruskal**: Sort edges by weight, add smallest edges that don't create cycles (using Union-Find).
**Prim**: Start from one node, always add smallest edge connecting tree to new node (using PQ).

**Properties:**
- Tree with V-1 edges
- Minimum total weight
- Unique if all edge weights are distinct

### 🎨 Visual Diagram
```
Kruskal:
Edges sorted: (0-1:2), (2-3:3), (1-2:4), (0-3:5), (1-3:6)

Step 1: Add 0-1 (2) → {0,1}, {2}, {3}
Step 2: Add 2-3 (3) → {0,1}, {2,3}
Step 3: Add 1-2 (4) → {0,1,2,3} (all connected)
MST weight = 2+3+4=9
```

### 🔧 Template Code
```java
// Kruskal's Algorithm
public int kruskalMST(int n, int[][] edges) { // edges: [u,v,w]
    Arrays.sort(edges, (a,b) -> a[2] - b[2]);
    DSU dsu = new DSU(n);
    int mstWeight = 0, edgesUsed = 0;
    
    for (int[] edge : edges) {
        if (dsu.union(edge[0], edge[1])) {
            mstWeight += edge[2];
            edgesUsed++;
            if (edgesUsed == n - 1) break;
        }
    }
    return edgesUsed == n - 1 ? mstWeight : -1;
}

// Prim's Algorithm
public int primMST(int n, List<int[]>[] graph) {
    boolean[] inMST = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[1] - b[1]);
    pq.offer(new int[]{0, 0}); // {node, weight to connect}
    
    int mstWeight = 0, nodesInMST = 0;
    
    while (!pq.isEmpty() && nodesInMST < n) {
        int[] curr = pq.poll();
        int u = curr[0], w = curr[1];
        if (inMST[u]) continue;
        
        inMST[u] = true;
        mstWeight += w;
        nodesInMST++;
        
        for (int[] edge : graph[u]) {
            int v = edge[0], weight = edge[1];
            if (!inMST[v]) pq.offer(new int[]{v, weight});
        }
    }
    return nodesInMST == n ? mstWeight : -1;
}
```

## **PATTERN 2: Critical and Pseudo-Critical Edges in MST**

### 📖 Theory
**Critical edge**: Must be in every MST (if removed, MST weight increases)
**Pseudo-critical edge**: Can be in some MSTs but not all
**Normal edge**: Never in any MST

**Properties:**
- Critical: edge weight < all other edges forming cycle
- For each edge, check if it's in MST and if removing forces higher weight

### 🎨 Visual Diagram
```
Graph: 0--2--1, 0--3--1 (all edges weight 2)
MST weight = 4

Edge (0-1) weight 3:
  Without (0-1), MST = 4
  With (0-1) forced, need other edges: 0-1(3)+0-2(2)+0-3(2)=7 >4
  So (0-1) is NOT in any MST → normal edge
```

### 🔧 Template Code
```java
public List<List<Integer>> findCriticalAndPseudoCriticalEdges(int n, int[][] edges) {
    int m = edges.length;
    // Add original index to edges
    int[][] edgesWithIdx = new int[m][4];
    for (int i = 0; i < m; i++) {
        System.arraycopy(edges[i], 0, edgesWithIdx[i], 0, 3);
        edgesWithIdx[i][3] = i;
    }
    
    // Sort by weight
    Arrays.sort(edgesWithIdx, (a,b) -> a[2] - b[2]);
    
    // Find normal MST weight
    int normalMSTWeight = kruskal(n, edgesWithIdx, -1, -1);
    
    List<Integer> critical = new ArrayList<>();
    List<Integer> pseudo = new ArrayList<>();
    
    for (int i = 0; i < m; i++) {
        // Check if critical: MST weight without this edge increases
        int withoutWeight = kruskal(n, edgesWithIdx, i, -1);
        if (withoutWeight > normalMSTWeight) {
            critical.add(i);
            continue;
        }
        
        // Check if pseudo: MST weight with this edge forced = normal weight
        int withWeight = kruskal(n, edgesWithIdx, -1, i);
        if (withWeight == normalMSTWeight) {
            pseudo.add(i);
        }
    }
    
    return Arrays.asList(critical, pseudo);
}

private int kruskal(int n, int[][] edges, int excludeIdx, int includeIdx) {
    DSU dsu = new DSU(n);
    int weight = 0, edgesUsed = 0;
    
    // Force include edge if specified
    if (includeIdx != -1) {
        int[] e = edges[includeIdx];
        dsu.union(e[0], e[1]);
        weight += e[2];
        edgesUsed++;
    }
    
    for (int[] e : edges) {
        if (e[3] == excludeIdx) continue;
        if (dsu.union(e[0], e[1])) {
            weight += e[2];
            edgesUsed++;
            if (edgesUsed == n - 1) break;
        }
    }
    return edgesUsed == n - 1 ? weight : Integer.MAX_VALUE;
}
```

## **PATTERN 3: Second Best MST / K-th Best MST**

### 📖 Theory
Second best MST is the minimum weight spanning tree that is **different from the best MST**. Approach: For each edge in MST, remove it and find MST on remaining graph.

**Properties:**
- Second best MST weight > best MST weight (if unique)
- Can be found in O(E log V + V²) using edge replacement

### 🎨 Visual Diagram
```
MST edges: e1, e2, e3 (weight sum=10)
Try removing e1 → find MST without e1 → weight=12
Try removing e2 → find MST without e2 → weight=11
Try removing e3 → find MST without e3 → weight=13
Second best = min(12,11,13) = 11
```

### 🔧 Template Code
```java
public int secondBestMST(int n, int[][] edges) {
    // Find best MST first
    Arrays.sort(edges, (a,b) -> a[2] - b[2]);
    DSU dsu = new DSU(n);
    List<int[]> mstEdges = new ArrayList<>();
    int bestWeight = 0;
    
    for (int[] e : edges) {
        if (dsu.union(e[0], e[1])) {
            bestWeight += e[2];
            mstEdges.add(e);
        }
    }
    
    // Find second best by removing each MST edge
    int secondBest = Integer.MAX_VALUE;
    for (int[] skipEdge : mstEdges) {
        DSU dsu2 = new DSU(n);
        int weight = 0;
        int edgesUsed = 0;
        
        for (int[] e : edges) {
            if (e == skipEdge) continue;
            if (dsu2.union(e[0], e[1])) {
                weight += e[2];
                edgesUsed++;
                if (edgesUsed == n - 1) break;
            }
        }
        if (edgesUsed == n - 1) {
            secondBest = Math.min(secondBest, weight);
        }
    }
    return secondBest;
}
```

## **PATTERN 4: Maximum Spanning Tree**

### 📖 Theory
Same as MST but with **maximum total weight**. Simply sort edges in **descending** order (Kruskal) or use negative weights (Prim).

**Properties:**
- Use negative weights in Prim
- Or sort edges descending in Kruskal
- Applications: Maximum bandwidth, maximum reliability

### 🎨 Visual Diagram
```
Edges sorted descending: (1-2:9), (0-1:8), (0-2:7), (2-3:6), (1-3:5)
Step 1: Add 1-2 (9)
Step 2: Add 0-1 (8)
Step 3: Add 2-3 (6) → all connected
Max MST weight = 9+8+6=23
```

### 🔧 Template Code
```java
public int maximumSpanningTree(int n, int[][] edges) {
    // Sort in descending order
    Arrays.sort(edges, (a,b) -> b[2] - a[2]);
    DSU dsu = new DSU(n);
    int maxWeight = 0, edgesUsed = 0;
    
    for (int[] edge : edges) {
        if (dsu.union(edge[0], edge[1])) {
            maxWeight += edge[2];
            edgesUsed++;
            if (edgesUsed == n - 1) break;
        }
    }
    return edgesUsed == n - 1 ? maxWeight : -1;
}
```

## **PATTERN 5: MST with Degree Constraints**

### 📖 Theory
Find MST where a specific node has **at most K edges** (degree constraint). Remove the node, find MST on remaining graph, then connect the node with K smallest edges.

**Properties:**
- NP-hard for general degree constraints
- For single node, solvable in O(E log E)

### 🎨 Visual Diagram
```
Node 0 has degree constraint ≤ 2
Without 0: MST on {1,2,3}
Then connect 0 to its 2 smallest edges to this MST
```

### 🔧 Template Code
```java
public int mstWithDegreeConstraint(int n, int[][] edges, int constrainedNode, int maxDegree) {
    // Separate edges connected to constrained node
    List<int[]> nodeEdges = new ArrayList<>();
    List<int[]> otherEdges = new ArrayList<>();
    
    for (int[] e : edges) {
        if (e[0] == constrainedNode || e[1] == constrainedNode) {
            nodeEdges.add(e);
        } else {
            otherEdges.add(e);
        }
    }
    
    // Sort edges not connected to constrained node
    otherEdges.sort((a,b) -> a[2] - b[2]);
    DSU dsu = new DSU(n);
    int weight = 0, edgesUsed = 0;
    
    // Build MST on graph without constrained node
    for (int[] e : otherEdges) {
        if (dsu.union(e[0], e[1])) {
            weight += e[2];
            edgesUsed++;
        }
    }
    
    // Connect constrained node with smallest edges
    nodeEdges.sort((a,b) -> a[2] - b[2]);
    int degree = 0;
    for (int[] e : nodeEdges) {
        if (degree < maxDegree && dsu.union(e[0], e[1])) {
            weight += e[2];
            degree++;
            edgesUsed++;
        }
    }
    
    return edgesUsed == n - 1 ? weight : -1;
}
```

## **PATTERN 6: MST with Pre-existing Edges / Forced Edges**

### 📖 Theory
Some edges are **already built** (cost 0) or **forced** to be in MST. Start DSU with these edges pre-unioned, then run standard MST.

**Properties:**
- Union forced edges first
- If forced edges create cycle → impossible
- Then add remaining edges

### 🎨 Visual Diagram
```
Forced edges: (0-1), (2-3)
Start DSU: {0,1}, {2,3}
Then add smallest edges connecting these components
```

### 🔧 Template Code
```java
public int mstWithForcedEdges(int n, int[][] allEdges, int[][] forcedEdges) {
    DSU dsu = new DSU(n);
    int weight = 0;
    int edgesUsed = 0;
    
    // Add forced edges first
    for (int[] e : forcedEdges) {
        if (!dsu.union(e[0], e[1])) {
            return -1;  // Forced edge creates cycle
        }
        weight += e[2];
        edgesUsed++;
    }
    
    // Sort remaining edges
    List<int[]> remaining = new ArrayList<>();
    for (int[] e : allEdges) remaining.add(e);
    remaining.sort((a,b) -> a[2] - b[2]);
    
    // Regular Kruskal
    for (int[] e : remaining) {
        if (dsu.union(e[0], e[1])) {
            weight += e[2];
            edgesUsed++;
            if (edgesUsed == n - 1) break;
        }
    }
    
    return edgesUsed == n - 1 ? weight : -1;
}
```

## **PATTERN 7: MST on Manhattan Distance / Complete Graph**

### 📖 Theory
When connecting points with Manhattan distance, you don't need all O(n²) edges. Only consider **neighbors in sorted order** (by x and y coordinates).

**Properties:**
- For Manhattan distance, only O(n) edges needed
- Sort points by x, connect consecutive points
- Sort points by y, connect consecutive points
- Then run Kruskal

### 🎨 Visual Diagram
```
Points: (0,0), (1,2), (3,1), (2,3)

Sort by x: (0,0)-(1,2) dist=3, (1,2)-(2,3) dist=2, (2,3)-(3,1) dist=3
Sort by y: (0,0)-(3,1) dist=4, (3,1)-(1,2) dist=3, (1,2)-(2,3) dist=2
Total unique edges to consider: O(n) instead of O(n²)
```

### 🔧 Template Code
```java
public int minCostConnectPoints(int[][] points) {
    int n = points.length;
    List<int[]> edges = new ArrayList<>();
    
    // Connect consecutive points by x-coordinate
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (a,b) -> points[a][0] - points[b][0]);
    for (int i = 0; i < n - 1; i++) {
        int dist = Math.abs(points[idx[i]][0] - points[idx[i+1]][0]) +
                   Math.abs(points[idx[i]][1] - points[idx[i+1]][1]);
        edges.add(new int[]{idx[i], idx[i+1], dist});
    }
    
    // Connect consecutive points by y-coordinate
    Arrays.sort(idx, (a,b) -> points[a][1] - points[b][1]);
    for (int i = 0; i < n - 1; i++) {
        int dist = Math.abs(points[idx[i]][0] - points[idx[i+1]][0]) +
                   Math.abs(points[idx[i]][1] - points[idx[i+1]][1]);
        edges.add(new int[]{idx[i], idx[i+1], dist});
    }
    
    // Kruskal on these O(n) edges
    edges.sort((a,b) -> a[2] - b[2]);
    DSU dsu = new DSU(n);
    int total = 0, edgesUsed = 0;
    
    for (int[] e : edges) {
        if (dsu.union(e[0], e[1])) {
            total += e[2];
            edgesUsed++;
            if (edgesUsed == n - 1) break;
        }
    }
    return total;
}
```

## **PATTERN 1: Basic Topological Sort (Kahn's Algorithm / DFS)**

### 📖 Theory
Order nodes such that for every edge u→v, u appears before v. Two approaches:
**Kahn's (BFS)**: Remove nodes with in-degree 0 repeatedly.
**DFS**: Process nodes in post-order, reverse the result.

**Properties:**
- Only possible on DAG
- If cycle exists, not all nodes will be processed

### 🎨 Visual Diagram
```
DAG: 0→1→3, 0→2→3, 2→4

Kahn's:
In-degrees: 0:0, 1:1, 2:1, 3:2, 4:1
Queue: [0]
Remove 0 → decrease in-degrees: 1:0, 2:0 → queue [1,2]
Remove 1 → decrease in-degree of 3: 3:1
Remove 2 → decrease in-degree of 3: 3:0, 4:0 → queue [3,4]
Remove 3, then 4
Order: 0,1,2,3,4
```

### 🔧 Template Code
```java
// Kahn's Algorithm (BFS)
public int[] topologicalSortKahn(int n, List<List<Integer>> graph) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++) {
        for (int v : graph.get(u)) {
            inDegree[v]++;
        }
    }
    
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) queue.offer(i);
    }
    
    int[] result = new int[n];
    int idx = 0;
    while (!queue.isEmpty()) {
        int u = queue.poll();
        result[idx++] = u;
        for (int v : graph.get(u)) {
            inDegree[v]--;
            if (inDegree[v] == 0) queue.offer(v);
        }
    }
    
    return idx == n ? result : new int[0];  // Empty if cycle exists
}

// DFS-based topological sort
public int[] topologicalSortDFS(int n, List<List<Integer>> graph) {
    boolean[] visited = new boolean[n];
    boolean[] inStack = new boolean[n];
    Stack<Integer> stack = new Stack<>();
    
    for (int i = 0; i < n; i++) {
        if (!visited[i]) {
            if (!dfs(i, graph, visited, inStack, stack)) {
                return new int[0];  // Cycle detected
            }
        }
    }
    
    int[] result = new int[n];
    for (int i = 0; i < n; i++) {
        result[i] = stack.pop();
    }
    return result;
}

private boolean dfs(int u, List<List<Integer>> graph, boolean[] visited, 
                    boolean[] inStack, Stack<Integer> stack) {
    visited[u] = true;
    inStack[u] = true;
    
    for (int v : graph.get(u)) {
        if (!visited[v]) {
            if (!dfs(v, graph, visited, inStack, stack)) return false;
        } else if (inStack[v]) {
            return false;  // Cycle detected
        }
    }
    
    inStack[u] = false;
    stack.push(u);
    return true;
}
```

## **PATTERN 2: Alien Dictionary (Character Ordering)**

### 📖 Theory
Given sorted words in an alien language, find the order of characters. Build graph where each adjacent word pair gives edge from first differing character to second.

**Properties:**
- Graph nodes = characters (26 letters)
- Edge u→v means u comes before v in alien alphabet
- Use topological sort on this graph

### 🎨 Visual Diagram
```
Words: ["wrt", "wrf", "er", "ett", "rftt"]
Compare "wrt" vs "wrf": 't' → 'f' (t before f)
Compare "wrf" vs "er": 'w' → 'e' (w before e)
Compare "er" vs "ett": 'r' → 't' (r before t)
Compare "ett" vs "rftt": 'e' → 'r' (e before r)

Graph: t→f, w→e, r→t, e→r
Topological order: w, e, r, t, f
```

### 🔧 Template Code
```java
public String alienOrder(String[] words) {
    // Build graph
    Map<Character, Set<Character>> graph = new HashMap<>();
    Map<Character, Integer> inDegree = new HashMap<>();
    
    // Initialize
    for (String word : words) {
        for (char c : word.toCharArray()) {
            graph.putIfAbsent(c, new HashSet<>());
            inDegree.putIfAbsent(c, 0);
        }
    }
    
    // Build edges
    for (int i = 0; i < words.length - 1; i++) {
        String w1 = words[i], w2 = words[i+1];
        int minLen = Math.min(w1.length(), w2.length());
        boolean found = false;
        
        for (int j = 0; j < minLen; j++) {
            char c1 = w1.charAt(j), c2 = w2.charAt(j);
            if (c1 != c2) {
                if (!graph.get(c1).contains(c2)) {
                    graph.get(c1).add(c2);
                    inDegree.put(c2, inDegree.get(c2) + 1);
                }
                found = true;
                break;
            }
        }
        
        // Check invalid case: "abc", "ab"
        if (!found && w1.length() > w2.length()) return "";
    }
    
    // Topological sort
    Queue<Character> queue = new LinkedList<>();
    for (char c : inDegree.keySet()) {
        if (inDegree.get(c) == 0) queue.offer(c);
    }
    
    StringBuilder sb = new StringBuilder();
    while (!queue.isEmpty()) {
        char c = queue.poll();
        sb.append(c);
        for (char next : graph.get(c)) {
            inDegree.put(next, inDegree.get(next) - 1);
            if (inDegree.get(next) == 0) queue.offer(next);
        }
    }
    
    return sb.length() == inDegree.size() ? sb.toString() : "";
}
```

## **PATTERN 3: Longest Path in DAG**

### 📖 Theory
In a DAG, longest path can be found using **DP on topological order**. Process nodes in topological order, update neighbors: `dp[v] = max(dp[v], dp[u] + weight(u→v))`.

**Properties:**
- Works only on DAG (no cycles)
- O(V + E) time complexity
- Also gives shortest path in DAG

### 🎨 Visual Diagram
```
DAG: 0→1(5), 0→2(3), 1→3(2), 2→3(4)

Topological order: 0,1,2,3
dp[0]=0
Process 0: dp[1]=5, dp[2]=3
Process 1: dp[3]=max(0,5+2=7)=7
Process 2: dp[3]=max(7,3+4=7)=7
Longest path: 0→1→3 weight=7
```

### 🔧 Template Code
```java
public int longestPathInDAG(int n, List<int[]>[] graph) {
    // Get topological order
    int[] topo = topologicalSortKahn(n, graph);
    
    int[] dp = new int[n];
    int longest = 0;
    
    for (int u : topo) {
        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            if (dp[u] + w > dp[v]) {
                dp[v] = dp[u] + w;
                longest = Math.max(longest, dp[v]);
            }
        }
    }
    return longest;
}
```

## **PATTERN 4: All Topological Orders (Backtracking)**

### 📖 Theory
When there are **multiple valid topological orders**, we need to generate all of them. Use backtracking with in-degree tracking.

**Properties:**
- Exponential number of possibilities (O(n!))
- Used in constraint satisfaction problems

### 🎨 Visual Diagram
```
Graph: 0→1, 0→2
Possible topological orders:
  [0,1,2]
  [0,2,1]
```

### 🔧 Template Code
```java
public List<List<Integer>> allTopologicalOrders(int n, List<List<Integer>> graph) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++) {
        for (int v : graph.get(u)) inDegree[v]++;
    }
    
    List<List<Integer>> result = new ArrayList<>();
    List<Integer> current = new ArrayList<>();
    boolean[] visited = new boolean[n];
    
    backtrack(n, graph, inDegree, visited, current, result);
    return result;
}

private void backtrack(int n, List<List<Integer>> graph, int[] inDegree, 
                       boolean[] visited, List<Integer> current, List<List<Integer>> result) {
    if (current.size() == n) {
        result.add(new ArrayList<>(current));
        return;
    }
    
    for (int u = 0; u < n; u++) {
        if (!visited[u] && inDegree[u] == 0) {
            // Choose u
            visited[u] = true;
            current.add(u);
            
            // Reduce in-degree of neighbors
            for (int v : graph.get(u)) inDegree[v]--;
            
            backtrack(n, graph, inDegree, visited, current, result);
            
            // Undo
            visited[u] = false;
            current.remove(current.size() - 1);
            for (int v : graph.get(u)) inDegree[v]++;
        }
    }
}
```

## **PATTERN 5: Minimum Time to Complete Tasks (Parallel Execution)**

### 📖 Theory
When tasks can be executed in **parallel** (unlimited workers), the minimum time is the longest path from start to node in terms of task duration. Each node's completion time = max(parent completion times) + node's duration.

**Properties:**
- Process in topological order
- Each node's time = max(incoming) + duration
- Total time = max of all node times

### 🎨 Visual Diagram
```
Tasks with duration: 0(2), 1(3), 2(1), 3(4)
Edges: 0→1, 0→2, 1→3, 2→3

Topological order: 0,1,2,3
time[0] = 2
time[1] = 2+3=5
time[2] = 2+1=3
time[3] = max(5,3)+4=9
Total time = 9
```

### 🔧 Template Code
```java
public int minimumTimeToCompleteTasks(int n, List<int[]>[] graph, int[] duration) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++) {
        for (int[] edge : graph[u]) inDegree[edge[0]]++;
    }
    
    Queue<Integer> queue = new LinkedList<>();
    int[] finishTime = new int[n];
    
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) {
            queue.offer(i);
            finishTime[i] = duration[i];
        }
    }
    
    while (!queue.isEmpty()) {
        int u = queue.poll();
        for (int[] edge : graph[u]) {
            int v = edge[0];
            finishTime[v] = Math.max(finishTime[v], finishTime[u] + duration[v]);
            inDegree[v]--;
            if (inDegree[v] == 0) queue.offer(v);
        }
    }
    
    int maxTime = 0;
    for (int t : finishTime) maxTime = Math.max(maxTime, t);
    return maxTime;
}
```

## **PATTERN 7: Lexicographically Smallest/Largest Topological Order**

### 📖 Theory
Use **min-heap** (for smallest) or **max-heap** (for largest) instead of regular queue in Kahn's algorithm. Always pick the smallest available node.

**Properties:**
- PQ instead of Queue
- Same time complexity O((V+E) log V)

### 🎨 Visual Diagram
```
Graph: 0→2, 1→2
Smallest topological order:
Available nodes with in-degree 0: {0,1}
Pick smallest: 0
Available: {1,2}? Wait, 2 still has in-degree 1
Pick 1
Then 2
Order: [0,1,2]
```

### 🔧 Template Code
```java
public int[] smallestTopologicalOrder(int n, List<List<Integer>> graph) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++) {
        for (int v : graph.get(u)) inDegree[v]++;
    }
    
    PriorityQueue<Integer> pq = new PriorityQueue<>(); // Min-heap for smallest
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) pq.offer(i);
    }
    
    int[] result = new int[n];
    int idx = 0;
    while (!pq.isEmpty()) {
        int u = pq.poll();
        result[idx++] = u;
        for (int v : graph.get(u)) {
            inDegree[v]--;
            if (inDegree[v] == 0) pq.offer(v);
        }
    }
    
    return idx == n ? result : new int[0];
}
```

## **PATTERN 8: Check Unique Topological Order**

### 📖 Theory
A DAG has a **unique topological order** if and only if at every step of Kahn's algorithm, there is exactly **one node** with in-degree 0.

**Properties:**
- If multiple nodes available → multiple orders possible
- Linear DAG (chain) has unique order

### 🎨 Visual Diagram
```
Graph with multiple orders: 0→1, 0→2
Kahn's: initial queue [0] (only one? Wait, only 0 has in-degree 0)
After removing 0, queue becomes [1,2] (two nodes!) → multiple orders

Graph with unique order: 0→1→2
Kahn's: [0] → remove 0 → [1] → remove 1 → [2] → unique
```

### 🔧 Template Code
```java
public boolean isUniqueTopologicalOrder(int n, List<List<Integer>> graph) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++) {
        for (int v : graph.get(u)) inDegree[v]++;
    }
    
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) queue.offer(i);
    }
    
    while (!queue.isEmpty()) {
        if (queue.size() > 1) return false;  // Multiple choices
        int u = queue.poll();
        for (int v : graph.get(u)) {
            inDegree[v]--;
            if (inDegree[v] == 0) queue.offer(v);
        }
    }
    return true;
}
```

## **PATTERN 9: Reconstruct Sequence from Subsequences**

### 📖 Theory
Given multiple sequences (subsequences of the original), reconstruct the original sequence if possible. Build graph from consecutive pairs in each sequence, then topological sort.

**Properties:**
- Each sequence gives constraints: a→b→c...
- If graph has cycle → impossible
- If multiple topological orders → not unique

### 🎨 Visual Diagram
```
Subsequences: [1,2,3], [1,3], [2,3]
Constraints: 1→2, 2→3, 1→3
Graph: 1→2→3, 1→3 (redundant)
Unique order: [1,2,3]
```

### 🔧 Template Code
```java
public int[] sequenceReconstruction(int[] org, List<List<Integer>> seqs) {
    int n = org.length;
    Map<Integer, Set<Integer>> graph = new HashMap<>();
    Map<Integer, Integer> inDegree = new HashMap<>();
    
    // Build graph
    for (List<Integer> seq : seqs) {
        for (int i = 0; i < seq.size(); i++) {
            graph.putIfAbsent(seq.get(i), new HashSet<>());
            inDegree.putIfAbsent(seq.get(i), 0);
            if (i > 0) {
                int prev = seq.get(i-1), curr = seq.get(i);
                if (graph.get(prev).add(curr)) {
                    inDegree.put(curr, inDegree.get(curr) + 1);
                }
            }
        }
    }
    
    // Topological sort
    Queue<Integer> queue = new LinkedList<>();
    for (int node : inDegree.keySet()) {
        if (inDegree.get(node) == 0) queue.offer(node);
    }
    
    List<Integer> result = new ArrayList<>();
    while (!queue.isEmpty()) {
        if (queue.size() > 1) return new int[0]; // Not unique
        int u = queue.poll();
        result.add(u);
        for (int v : graph.getOrDefault(u, new HashSet<>())) {
            inDegree.put(v, inDegree.get(v) - 1);
            if (inDegree.get(v) == 0) queue.offer(v);
        }
    }
    
    // Check if matches original
    if (result.size() != n) return new int[0];
    for (int i = 0; i < n; i++) {
        if (result.get(i) != org[i]) return new int[0];
    }
    return result.stream().mapToInt(i->i).toArray();
}
```

## **PATTERN 1: Cycle Detection in Directed Graph (DFS with 3 States)**

### 📖 Theory
Use **3 states**: 0=unvisited, 1=visiting (in current recursion stack), 2=processed. If we find an edge to a node with state=1, we found a cycle.

**Properties:**
- State 1 = in current DFS path
- Back edge = cycle detected
- Also works with Kahn's algorithm (if not all nodes processed)

### 🎨 Visual Diagram
```
Graph: 0→1→2→0 (cycle)
DFS from 0:
  visit 0 (state 1)
    visit 1 (state 1)
      visit 2 (state 1)
        neighbor 0 → state 1! CYCLE DETECTED!

State tracking:
0: visiting, 1: visiting, 2: visiting → back edge 2→0
```

### 🔧 Template Code
```java
public boolean hasCycleDirected(int n, List<List<Integer>> graph) {
    int[] state = new int[n]; // 0=unvisited, 1=visiting, 2=processed
    
    for (int i = 0; i < n; i++) {
        if (state[i] == 0 && dfsCycle(i, graph, state)) {
            return true;
        }
    }
    return false;
}

private boolean dfsCycle(int u, List<List<Integer>> graph, int[] state) {
    state[u] = 1; // visiting
    
    for (int v : graph.get(u)) {
        if (state[v] == 1) return true; // back edge
        if (state[v] == 0 && dfsCycle(v, graph, state)) return true;
    }
    
    state[u] = 2; // processed
    return false;
}
```

## **PATTERN 2: Cycle Detection in Undirected Graph (DFS with Parent)**

### 📖 Theory
In undirected graph, a cycle exists if we encounter an **already visited node** that is NOT the parent. Use DFS with parent tracking.

**Properties:**
- Parent tracking prevents false cycles
- Union-Find also works (Pattern 6)

### 🎨 Visual Diagram
```
Graph: 0-1-2-0 (triangle)
DFS from 0:
  visit 0
    neighbor 1 (parent 0): visit 1
      neighbor 0 (parent 1) → parent, skip
      neighbor 2 (parent 1): visit 2
        neighbor 1 (parent 2) → parent, skip
        neighbor 0 (parent 2) → visited and NOT parent! CYCLE!

Parent tracking prevents 1-0 from being counted as cycle
```

### 🔧 Template Code
```java
public boolean hasCycleUndirected(int n, List<List<Integer>> graph) {
    boolean[] visited = new boolean[n];
    
    for (int i = 0; i < n; i++) {
        if (!visited[i] && dfsCycle(i, -1, graph, visited)) {
            return true;
        }
    }
    return false;
}

private boolean dfsCycle(int u, int parent, List<List<Integer>> graph, boolean[] visited) {
    visited[u] = true;
    
    for (int v : graph.get(u)) {
        if (v == parent) continue; // skip parent
        if (visited[v]) return true; // found cycle
        if (dfsCycle(v, u, graph, visited)) return true;
    }
    return false;
}
```

## **PATTERN 3: Find and Print the Cycle**

### 📖 Theory
Not just detect cycle, but **find the nodes in the cycle**. Use parent array during DFS. When cycle is found, backtrack to reconstruct cycle.

**Properties:**
- Store parent for each node during DFS
- When cycle detected, trace back using parent

### 🎨 Visual Diagram
```
Graph: 0-1-2-0
DFS from 0:
  parent[0] = -1
  parent[1] = 0
  parent[2] = 1
  From 2, neighbor 0: visited and not parent (0 != 1)
Cycle nodes: start from 2, go parent[2]=1, parent[1]=0
Cycle: [2,1,0]
```

### 🔧 Template Code
```java
public List<Integer> findCycleUndirected(int n, List<List<Integer>> graph) {
    int[] parent = new int[n];
    Arrays.fill(parent, -1);
    boolean[] visited = new boolean[n];
    int[] cycleStart = new int[1];
    
    for (int i = 0; i < n; i++) {
        if (!visited[i]) {
            if (dfsFindCycle(i, -1, graph, visited, parent, cycleStart)) {
                return reconstructCycle(parent, cycleStart[0]);
            }
        }
    }
    return new ArrayList<>();
}

private boolean dfsFindCycle(int u, int p, List<List<Integer>> graph, 
                              boolean[] visited, int[] parent, int[] cycleStart) {
    visited[u] = true;
    parent[u] = p;
    
    for (int v : graph.get(u)) {
        if (v == p) continue;
        if (visited[v]) {
            cycleStart[0] = u;
            return true;
        }
        if (dfsFindCycle(v, u, graph, visited, parent, cycleStart)) {
            return true;
        }
    }
    return false;
}

private List<Integer> reconstructCycle(int[] parent, int start) {
    List<Integer> cycle = new ArrayList<>();
    int current = start;
    do {
        cycle.add(current);
        current = parent[current];
    } while (current != start && current != -1);
    cycle.add(start);
    return cycle;
}
```

## **PATTERN 4: Find All Nodes in Any Cycle**

### 📖 Theory
Find all nodes that are **part of at least one cycle**. Use Kahn's algorithm (topological sort removal) - nodes remaining after removing all nodes with in-degree 0 are cycle nodes.

**Properties:**
- Remove nodes with in-degree 0 repeatedly
- Remaining nodes form cycles

### 🎨 Visual Diagram
```
Graph: 0→1, 1→2, 2→1 (cycle between 1-2), 0→3

Step 1: in-degree: 0:0, 1:2, 2:1, 3:1
Remove node 0 (in-degree 0) → reduce in-degree of 1,3
Now in-degree: 1:1, 2:1, 3:0
Remove node 3 (in-degree 0)
Now in-degree: 1:1, 2:1 (no nodes with in-degree 0)
Cycle nodes: {1,2}
```

### 🔧 Template Code
```java
public List<Integer> findNodesInCycle(int n, List<List<Integer>> graph) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++) {
        for (int v : graph.get(u)) inDegree[v]++;
    }
    
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) queue.offer(i);
    }
    
    boolean[] inCycle = new boolean[n];
    Arrays.fill(inCycle, true);
    
    while (!queue.isEmpty()) {
        int u = queue.poll();
        inCycle[u] = false;
        for (int v : graph.get(u)) {
            inDegree[v]--;
            if (inDegree[v] == 0) queue.offer(v);
        }
    }
    
    List<Integer> result = new ArrayList<>();
    for (int i = 0; i < n; i++) {
        if (inCycle[i]) result.add(i);
    }
    return result;
}
```

## **PATTERN 5: Minimum Edges to Remove to Break Cycle**

### 📖 Theory
For undirected graph, to break all cycles, remove **E - (V - C)** edges where C = number of connected components. Actually, minimum edges to remove = E - (V - C) for making tree? Wait...

**Properties:**
- Tree has V-1 edges per component
- If a component has E edges and V nodes, cycles = E - (V - 1)
- Minimum edges to remove = sum over components of (E_i - (V_i - 1))

### 🎨 Visual Diagram
```
Component: V=4, E=5
Tree would have V-1=3 edges
Cycles = 5-3=2 edges to remove
```

### 🔧 Template Code
```java
public int minEdgesToRemoveToBreakCycles(int n, List<List<Integer>> graph) {
    boolean[] visited = new boolean[n];
    int totalEdges = 0;
    int totalNodes = 0;
    int treeEdges = 0;
    
    for (int i = 0; i < n; i++) {
        if (!visited[i]) {
            int[] comp = new int[2]; // [nodes, edges]
            dfsCount(i, -1, graph, visited, comp);
            totalNodes += comp[0];
            totalEdges += comp[1];
            treeEdges += comp[0] - 1;
        }
    }
    
    // For each component, edges to remove = edges - (nodes - 1)
    // Total edges to remove = totalEdges - (totalNodes - components)
    int components = 0;
    Arrays.fill(visited, false);
    for (int i = 0; i < n; i++) {
        if (!visited[i]) {
            components++;
            dfsMark(i, graph, visited);
        }
    }
    
    return totalEdges - (totalNodes - components);
}

private void dfsCount(int u, int parent, List<List<Integer>> graph, 
                       boolean[] visited, int[] comp) {
    visited[u] = true;
    comp[0]++; // nodes count
    for (int v : graph.get(u)) {
        comp[1]++; // edges count (will count each edge twice)
        if (!visited[v]) {
            dfsCount(v, u, graph, visited, comp);
        }
    }
}
```

## **PATTERN 6: Cycle Detection using Union-Find (DSU)**

### 📖 Theory
In undirected graph, when adding edges, if find(u) == find(v) before union, then adding this edge creates a cycle. Perfect for dynamic edge addition.

**Properties:**
- O(α(n)) per operation
- No DFS recursion overhead

### 🎨 Visual Diagram
```
Edges added in order:
1. (0,1): find(0)!=find(1) → union ✅
2. (1,2): find(1)!=find(2) → union ✅
3. (2,0): find(2)==find(0) → CYCLE! ❌
```

### 🔧 Template Code
```java
class DSU {
    int[] parent, rank;
    DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false; // cycle detected
        if (rank[px] < rank[py]) parent[px] = py;
        else if (rank[px] > rank[py]) parent[py] = px;
        else { parent[py] = px; rank[px]++; }
        return true;
    }
}

public boolean hasCycleDSU(int n, int[][] edges) {
    DSU dsu = new DSU(n);
    for (int[] e : edges) {
        if (!dsu.union(e[0], e[1])) return true;
    }
    return false;
}
```

## **PATTERN 7: Longest Cycle in Graph**

### 📖 Theory
Find the cycle with maximum number of nodes. For directed graphs, use DFS with state and distance tracking. When back edge found, cycle length = current_depth - depth[neighbor] + 1.

**Properties:**
- Track depth of each node during DFS
- When cycle found, compute length
- Keep maximum

### 🎨 Visual Diagram
```
Graph: 0→1→2→3→1 (cycle 1→2→3→1 length=3)
DFS from 0:
  depth[0]=0
    depth[1]=1
      depth[2]=2
        depth[3]=3
          neighbor 1, depth[1]=1
          cycle length = 3-1+1=3
```

### 🔧 Template Code
```java
public int longestCycle(int n, int[] edges) { // edges[i] = next node or -1
    int[] depth = new int[n];
    int[] state = new int[n]; // 0=unvisited,1=visiting,2=processed
    int maxCycle = -1;
    
    for (int i = 0; i < n; i++) {
        if (state[i] == 0) {
            maxCycle = Math.max(maxCycle, dfsLongestCycle(i, edges, depth, state, 0));
        }
    }
    return maxCycle;
}

private int dfsLongestCycle(int u, int[] edges, int[] depth, int[] state, int currDepth) {
    if (edges[u] == -1) {
        state[u] = 2;
        return -1;
    }
    
    if (state[u] == 1) {
        return currDepth - depth[u]; // cycle length
    }
    
    if (state[u] == 2) return -1;
    
    state[u] = 1;
    depth[u] = currDepth;
    int cycleLen = dfsLongestCycle(edges[u], edges, depth, state, currDepth + 1);
    state[u] = 2;
    return cycleLen;
}
```

public boolean validTree(int n, int[][] edges) {
    // Check edge count
    if (edges.length != n - 1) return false;
    
    // Build graph
    List<List<Integer>> graph = new ArrayList<>();
    for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
    for (int[] e : edges) {
        graph.get(e[0]).add(e[1]);
        graph.get(e[1]).add(e[0]);
    }
    
    // Check connectivity and no cycles
    boolean[] visited = new boolean[n];
    if (hasCycleDFS(0, -1, graph, visited)) return false;
    
    // Check all nodes visited (connected)
    for (boolean v : visited) if (!v) return false;
    return true;
}

private boolean hasCycleDFS(int u, int parent, List<List<Integer>> graph, boolean[] visited) {
    visited[u] = true;
    for (int v : graph.get(u)) {
        if (v == parent) continue;
        if (visited[v]) return true;
        if (hasCycleDFS(v, u, graph, visited)) return true;
    }
    return false;
}
