## Chapter 1: Spring Boot Project Setup & Build Tools

### Q1: What is Spring Boot and how is it different from Spring Framework?

**Answer:**

Spring Boot is a project built on top of the Spring Framework that provides auto-configuration, starter dependencies, and embedded servers to simplify Spring application development.

**Key Differences:**

| Feature | Spring Framework | Spring Boot |
|---------|-----------------|-------------|
| **Configuration** | Manual XML/Java config | Auto-configuration |
| **Dependencies** | Manual version management | Starter POMs |
| **Server** | Requires external server (Tomcat) | Embedded server (Tomcat, Jetty, Undertow) |
| **Deployment** | WAR file to external server | JAR with embedded server |
| **Setup time** | Days/weeks | Minutes |

**Interview Tip:** Emphasize that Spring Boot is not a replacement but an enhancement to Spring Framework that follows "convention over configuration."

### Q3: What is the difference between Maven and Gradle?

**Answer:**

Both are build automation tools, but they have different approaches.

| Aspect | Maven | Gradle |
|--------|-------|--------|
| **Configuration language** | XML | Groovy/Kotlin DSL |
| **Convention** | Convention over configuration | Flexible |
| **Performance** | Slower (no incremental builds) | Faster (incremental builds, build cache) |
| **Learning curve** | Moderate | Steeper |
| **Build file** | pom.xml | build.gradle / build.gradle.kts |
| **Plugin ecosystem** | Mature | Growing |
| **Multi-project builds** | Supported | Excellent |

**Maven pom.xml example:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.2.0</version>
    </parent>
    
    <groupId>com.example</groupId>
    <artifactId>demo</artifactId>
    <version>0.0.1-SNAPSHOT</version>
    
    <properties>
        <java.version>17</java.version>
    </properties>
    
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-data-jpa</artifactId>
        </dependency>

```

## Chapter 2: Annotations & Configuration

### Q4: What are the most important Spring Boot annotations?

**Answer:**

Here are the essential Spring Boot annotations categorized by purpose:

**Core Spring Boot Annotations:**

| Annotation | Purpose |
|------------|---------|
| `@SpringBootApplication` | Combines `@Configuration`, `@EnableAutoConfiguration`, `@ComponentScan` |
| `@EnableAutoConfiguration` | Enables Spring Boot's auto-configuration |
| `@ComponentScan` | Scans for components in package and sub-packages |

**Stereo type Annotations:**

| Annotation | Purpose |
|------------|---------|
| `@Component` | Generic Spring-managed bean |
| `@Service` | Service layer bean (business logic) |
| `@Repository` | DAO layer bean (database operations) |
| `@Controller` | Web controller (returns view) |
| `@RestController` | `@Controller` + `@ResponseBody` (REST API) |

**Configuration Annotations:**

| Annotation | Purpose |
|------------|---------|
| `@Configuration` | Indicates class has `@Bean` definitions |
| `@Bean` | Declares a Spring-managed bean |
| `@Autowired` | Injects dependencies |
| `@Value` | Injects values from properties files |
| `@ConfigurationProperties` | Binds external properties to Java objects |

**Example:**

```java
@SpringBootApplication  // Combines @Configuration, @EnableAutoConfiguration, @ComponentScan
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

@Service
public class UserService {
    @Autowired
    private UserRepository userRepository;
    
    @Value("${app.name}")
    private String appName;
}

@RestController
@RequestMapping("/api/users")
public class UserController {
    private final UserService userService;
    
    // Constructor injection (recommended)
    public UserController(UserService userService) {
        this.userService = userService;
    }
}

@Repository
public interface UserRepository extends JpaRepository<User, Long> {
}

@Configuration
public class AppConfig {
    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}
```

**Interview Tip:** Explain the difference between `@Component`, `@Service`, `@Repository`, and `@Controller` - they are all specialized forms of `@Component` for different layers, adding specific behaviors.

### Q5: What is the difference between @Component, @Service, @Repository, and @Controller?

**Answer:**

All are stereotypes for Spring-managed beans, but they have different purposes and additional behaviors.

| Annotation | Layer | Additional Behavior |
|------------|-------|---------------------|
| `@Component` | Generic | No additional behavior |
| `@Service` | Service (business logic) | None (semantic only) |
| `@Repository` | DAO (data access) | Translates persistence exceptions |
| `@Controller` | Web controller | Enables web request handling |
| `@RestController` | REST controller | `@Controller` + `@ResponseBody` |

**Key differences:**

1. **@Repository** - Spring automatically translates persistence-specific exceptions (like SQLException) into Spring's DataAccessException hierarchy.

2. **@Controller** - Works with view resolvers, returns view names. Used with `@ResponseBody` to return JSON.

3. **@RestController** - Combines `@Controller` and `@ResponseBody`. Every method returns JSON/XML directly.

**Example:**

```java
// Generic component - Spring manages it but no special behavior
@Component
public class UtilityHelper {
    public String formatDate(Date date) {
        // formatting logic
    }
}

// Service layer - business logic
@Service
public class OrderService {
    // Business logic here
}

// Repository - data access with exception translation
@Repository
public class UserRepository {
    // Database operations - exceptions are translated automatically
}

// Traditional controller - returns view name
@Controller
public class HomeController {
    @GetMapping("/home")
    public String home(Model model) {
        model.addAttribute("message", "Hello");
        return "home"; // Returns view name (home.html)
    }
}

// REST controller - returns JSON directly
@RestController
@RequestMapping("/api/users")
public class UserRestController {
    @GetMapping("/{id}")
    public User getUser(@PathVariable Long id) {
        return userService.findById(id); // Returns JSON
    }
}
```

## Chapter 3: REST API Annotations

### Q6: Explain @GetMapping, @PostMapping, @PutMapping, @DeleteMapping with examples.

**Answer:**

These are composed annotations for HTTP methods in REST APIs, alternatives to `@RequestMapping(method = RequestMethod.GET)`.

**Mapping Annotations:**

| Annotation | HTTP Method | Purpose |
|------------|-------------|---------|
| `@GetMapping` | GET | Retrieve data |
| `@PostMapping` | POST | Create new resource |
| `@PutMapping` | PUT | Update entire resource |
| `@PatchMapping` | PATCH | Update partial resource |
| `@DeleteMapping` | DELETE | Delete resource |

**Complete Example:**

```java
@RestController
@RequestMapping("/api/products")
public class ProductController {
    
    @Autowired
    private ProductService productService;
    
    // GET /api/products - Get all products
    @GetMapping
    public List<Product> getAllProducts() {
        return productService.findAll();
    }
    
    // GET /api/products/123 - Get product by ID
    @GetMapping("/{id}")
    public Product getProductById(@PathVariable Long id) {
        return productService.findById(id);
    }
    
    // POST /api/products - Create new product
    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Product createProduct(@RequestBody Product product) {
        return productService.save(product);
    }
    
    // PUT /api/products/123 - Update entire product
    @PutMapping("/{id}")
    public Product updateProduct(@PathVariable Long id, @RequestBody Product product) {
        product.setId(id);
        return productService.update(product);
    }
    
    // PATCH /api/products/123 - Update partial product
    @PatchMapping("/{id}")
    public Product patchProduct(@PathVariable Long id, @RequestBody Map<String, Object> updates) {
        return productService.patch(id, updates);
    }
    
    // DELETE /api/products/123 - Delete product
    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void deleteProduct(@PathVariable Long id) {
        productService.deleteById(id);
    }
}
```

**HTTP Status Codes Best Practices:**

| Method | Success Status | Created Status | No Content Status |
|--------|---------------|----------------|-------------------|
| GET | 200 OK | - | 204 No Content |
| POST | 200 OK | 201 Created | - |
| PUT | 200 OK | - | 204 No Content |
| DELETE | - | - | 204 No Content |

**Interview Tip:** Explain that these annotations are meta-annotations of `@RequestMapping` with specific HTTP methods, available since Spring 4.3.

## Chapter 4: Path Variables & Request Parameters

### Q7: How do you handle path variables and request parameters in Spring Boot?

**Answer:**

Spring Boot provides annotations to extract data from the request URL.

**Path Variables (@PathVariable):**
- Extracts values from URL path
- Used for resource identification (e.g., /users/123)

**Request Parameters (@RequestParam):**
- Extracts query parameters
- Used for filtering, pagination (e.g., /users?page=1&size=10)

**Example:**

```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    // Path variable: /api/users/123
    @GetMapping("/{userId}")
    public User getUserById(@PathVariable Long userId) {
        return userService.findById(userId);
    }
    
    // Path variable with custom name
    @GetMapping("/{userId}/orders/{orderId}")
    public Order getUserOrder(@PathVariable("userId") Long userId, 
                              @PathVariable("orderId") Long orderId) {
        return orderService.findByUserAndOrder(userId, orderId);
    }
    
    // Optional path variable (required = false)
    @GetMapping("/{userId}/profile")
    public UserProfile getUserProfile(@PathVariable Long userId,
                                      @PathVariable(required = false) String section) {
        return userService.getProfile(userId, section);
    }
    
    // Request parameters: /api/users?page=0&size=10&sort=name,asc
    @GetMapping
    public Page<User> getUsers(@RequestParam(defaultValue = "0") int page,
                               @RequestParam(defaultValue = "10") int size,
                               @RequestParam(defaultValue = "id,asc") String[] sort) {
        Pageable pageable = PageRequest.of(page, size, Sort.by(sort));
        return userService.findAll(pageable);
    }
    
    // Optional request parameter
    @GetMapping("/search")
    public List<User> searchUsers(@RequestParam(required = false) String name,
                                  @RequestParam(required = false) String email) {
        return userService.search(name, email);
    }
    
    // Map all request parameters
    @GetMapping("/filter")
    public List<User> filterUsers(@RequestParam Map<String, String> allParams) {
        return userService.filter(allParams);
    }
}
```

**Comparison Table:**

| Aspect | @PathVariable | @RequestParam |
|--------|---------------|---------------|
| **Location** | URL path | Query string |
| **Example** | /users/123 | /users?id=123 |
| **Required by default** | Yes | Yes |
| **Use case** | Resource identification | Filtering, pagination |

**Interview Tip:** Mention that you can combine both in a single endpoint: `/users/{userId}/orders?status=COMPLETED`.

## Chapter 5: Database Connection

### Q8: How do you configure database connections for H2, MySQL, and PostgreSQL?

**Answer:**

Spring Boot uses `application.properties` or `application.yml` for database configuration.

**1. H2 (In-Memory Database) - For Development/Testing:**

```properties
# application.properties
spring.datasource.url=jdbc:h2:mem:testdb
spring.datasource.driverClassName=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

# H2 Console
spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

# JPA
spring.jpa.database-platform=org.hibernate.dialect.H2Dialect
spring.jpa.hibernate.ddl-auto=create-drop
spring.jpa.show-sql=true
```

**2. MySQL Configuration:**

```properties
# application.properties
spring.datasource.url=jdbc:mysql://localhost:3306/mydb?useSSL=false&serverTimezone=UTC
spring.datasource.username=root
spring.datasource.password=password
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

# JPA
spring.jpa.database-platform=org.hibernate.dialect.MySQL8Dialect
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

**3. PostgreSQL Configuration:**

```properties
# application.properties
spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
spring.datasource.username=postgres
spring.datasource.password=password
spring.datasource.driver-class-name=org.postgresql.Driver

# JPA
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

**Environment-specific configuration using profiles:**

```properties
# application-dev.properties (Development - H2)
spring.datasource.url=jdbc:h2:mem:testdb
spring.jpa.hibernate.ddl-auto=create-drop

```

**Dependencies (pom.xml):**

**Interview Tip:** Explain the difference between DDL-AUTO options:

- `validate`: Validates schema without changes
- `none`: No schema changes

## Chapter 6: JPA Repository

### Q9: What is the difference between JpaRepository and CrudRepository?

**Answer:**

Both are Spring Data JPA interfaces, but they provide different levels of functionality.

**Inheritance Hierarchy:**

```
Repository (marker interface)
    │
    └── CrudRepository (basic CRUD operations)
            │
            └── PagingAndSortingRepository (pagination + sorting)
                    │
                    └── JpaRepository (JPA-specific methods)
```

**Comparison Table:**

| Feature | CrudRepository | JpaRepository |
|---------|---------------|---------------|
| **Save entity** | `save()`, `saveAll()` | Same |
| **Find by ID** | `findById()` | Same |
| **Find all** | `findAll()` | `findAll()`, `findAll(Sort)`, `findAll(Pageable)` |
| **Delete** | `delete()`, `deleteById()`, `deleteAll()` | Same |
| **Count** | `count()` | Same |
| **Exists** | `existsById()` | Same |
| **Flush** | No | `flush()`, `saveAndFlush()` |
| **Delete in batch** | No | `deleteInBatch()`, `deleteAllInBatch()` |
| **Get reference** | No | `getReferenceById()` (lazy loading) |

**Example Implementation:**

```java
// Entity
@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(nullable = false, unique = true)
    private String email;
    
    private String name;
    
    // Constructors, getters, setters...
}

// Using CrudRepository
@Repository
public interface UserCrudRepository extends CrudRepository<User, Long> {
    // Custom query methods
    Optional<User> findByEmail(String email);
    List<User> findByNameContaining(String name);
}

// Using JpaRepository (more features)
@Repository
public interface UserJpaRepository extends JpaRepository<User, Long> {
    // Same custom methods plus all JpaRepository features
    
    // Pagination and sorting
    Page<User> findByNameContaining(String name, Pageable pageable);
    
    // Native query
    @Query(value = "SELECT * FROM users WHERE email = ?1", nativeQuery = true)
    Optional<User> findByEmailNative(String email);
    
    // JPQL query
    @Query("SELECT u FROM User u WHERE u.email = ?1")
    Optional<User> findByEmailJPQL(String email);
    
    // Update query
    @Modifying
    @Transactional
    @Query("UPDATE User u SET u.name = ?2 WHERE u.id = ?1")
    int updateUserName(Long id, String name);
}

// Usage
@Service
public class UserService {
    
    @Autowired
    private UserJpaRepository userRepository;
    
    public User saveUser(User user) {
        return userRepository.save(user);
    }
    
    public User saveAndFlush(User user) {
        return userRepository.saveAndFlush(user); // Immediately persists
    }
    
    public Page<User> getUsers(int page, int size) {
        Pageable pageable = PageRequest.of(page, size, Sort.by("name").ascending());
        return userRepository.findAll(pageable);
    }
    
    public void deleteInBatch(List<User> users) {
        userRepository.deleteInBatch(users); // Batch delete
    }
}
```

**Interview Tip:** Recommend using `JpaRepository` when you need pagination, sorting, or batch operations. Use `CrudRepository` for simple CRUD operations.

## Chapter 7: Spring Boot DevTools & Hot Reloading

### Q10: What is Spring Boot DevTools and how do you enable hot reloading?

**Answer:**

Spring Boot DevTools provides development-time features including automatic restart, live reload, and property defaults for development.

**Key Features:**

| Feature | Description |
|---------|-------------|
| **Automatic Restart** | Restarts application when files change |
| **LiveReload** | Automatically refreshes browser |
| **Property defaults** | Disables template caching, enables debug logging |
| **Remote debugging** | Supports remote application debugging |

**Setup (pom.xml):**

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <scope>runtime</scope>
    <optional>true</optional>
</dependency>
```

**Configuration (application.properties):**

```properties
# Restart trigger files
spring.devtools.restart.additional-paths=src/main/resources
spring.devtools.restart.exclude=static/**,public/**

# Disable restart for specific resources
spring.devtools.restart.enabled=true

# LiveReload
spring.devtools.livereload.enabled=true
spring.devtools.livereload.port=35729

# Remote debugging
spring.devtools.remote.secret=mysecret
spring.devtools.remote.context-path=/debug
```

**How it works:**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    DEVTOOLS HOT RELOADING WORKFLOW                           │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                               │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐                  │
│  │   Save file  │───▶│ DevTools     │───▶│   Restart    │                  │
│  │   (.java)    │    │ detects      │    │   (if needed)│                  │
│  │              │    │ change       │    │              │                  │
│  └──────────────┘    └──────────────┘    └──────────────┘                  │
│                                                  │                           │
│                                                  │                           │
│  ┌──────────────┐    ┌──────────────┐           │                           │
│  │   Browser    │◀───│  LiveReload  │◀──────────┘                           │
│  │   refreshes  │    │   triggers   │                                      │
│  └──────────────┘    └──────────────┘                                      │
│                                                                               │
└─────────────────────────────────────────────────────────────────────────────┘
```

**Class Loader Structure:**

- **Base ClassLoader:** Loads libraries (JARs) - NOT restarted
- **Restart ClassLoader:** Loads application classes - RESTARTED on changes

**Interview Tip:** Explain that DevTools uses two class loaders, so restart is faster than a full JVM restart because only application classes are reloaded.

## Chapter 8: Spring Batch & Scheduling

### Q11: How do you implement scheduling in Spring Boot using cron expressions?

**Answer:**

Spring Boot provides `@Scheduled` annotation for task scheduling with cron expressions, fixed rate, or fixed delay.

**Enable Scheduling:**

```java
@SpringBootApplication
```

```java
public class ScheduledTasks {

    // 1. Fixed Rate - runs every 5 seconds (regardless of previous execution)
    @Scheduled(fixedRate = 5000)
    public void reportCurrentTime() {
        logger.info("Current time: {}", new Date());
    }
    
    // 2. Fixed Delay - runs 5 seconds after previous execution completes
    @Scheduled(fixedDelay = 5000)
    public void processData() {
        logger.info("Processing data...");
        // Long running task
    }
    
    // 3. Initial Delay - waits 10 seconds before first execution
    @Scheduled(initialDelay = 10000, fixedRate = 5000)
    public void delayedStart() {
        logger.info("Started after initial delay");
    }
    
    // 4. Cron Expression - runs at 10:15 AM every day
    @Scheduled(cron = "0 15 10 * * ?")
    public void dailyReport() {
        logger.info("Generating daily report");
    }
    
    // 5. Cron Expression - runs every weekday at 9 AM
    @Scheduled(cron = "0 0 9 * * MON-FRI")
    public void weekdayTask() {
        logger.info("Weekday morning task");
    }
}
```

```
│ │ │ │ ┌───────────── month (1-12)
│ │ │ │ │ ┌───────────── day of week (0-7) (SUN=0 or 7)
```

```java
@ControllerAdvice
public class GlobalExceptionHandler {
    
    private static final Logger logger = LoggerFactory.getLogger(GlobalExceptionHandler.class);
    
    // Handle specific exception
    @ExceptionHandler(ResourceNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ResponseEntity<ErrorResponse> handleResourceNotFound(ResourceNotFoundException ex, 
                                                                  WebRequest request) {
        logger.error("Resource not found: {}", ex.getMessage());
        ErrorResponse errorResponse = new ErrorResponse(
            HttpStatus.NOT_FOUND.value(),
            "Not Found",
            ex.getMessage(),
            request.getDescription(false)
        );
        return new ResponseEntity<>(errorResponse, HttpStatus.NOT_FOUND);
    }
    
    // Handle validation exception with field errors
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ResponseEntity<ErrorResponse> handleValidationExceptions(MethodArgumentNotValidException ex,
                                                                      WebRequest request) {
        Map<String, String> errors = new HashMap<>();
        ex.getBindingResult().getAllErrors().forEach((error) -> {
            String fieldName = ((FieldError) error).getField();
            String errorMessage = error.getDefaultMessage();
            errors.put(fieldName, errorMessage);
        });
        
        ErrorResponse errorResponse = new ErrorResponse(
            HttpStatus.BAD_REQUEST.value(),
            "Validation Failed",
            "Invalid input data",
            request.getDescription(false)
        );
        errorResponse.setValidationErrors(errors);
        return new ResponseEntity<>(errorResponse, HttpStatus.BAD_REQUEST);
    }
    
    // Handle generic exception
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public ResponseEntity<ErrorResponse> handleGenericException(Exception ex, 
                                                                  WebRequest request) {
        logger.error("Unexpected error: ", ex);
        ErrorResponse errorResponse = new ErrorResponse(
            HttpStatus.INTERNAL_SERVER_ERROR.value(),
            "Internal Server Error",
            "An unexpected error occurred",
            request.getDescription(false)
        );
        return new ResponseEntity<>(errorResponse, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
```

**JWT Utility Service:**

```java
@Component
public class JwtUtil {
    
    @Value("${jwt.secret}")
    private String secret;
    
    @Value("${jwt.expiration}")
    private Long expiration;
    
    // Generate token
    public String generateToken(String username) {
        Map<String, Object> claims = new HashMap<>();
        return createToken(claims, username);
    }
    
    private String createToken(Map<String, Object> claims, String subject) {
        return Jwts.builder()
            .setClaims(claims)
            .setSubject(subject)
            .setIssuedAt(new Date(System.currentTimeMillis()))
            .setExpiration(new Date(System.currentTimeMillis() + expiration))
            .signWith(getSignKey(), SignatureAlgorithm.HS256)
            .compact();
    }
    
    private Key getSignKey() {
        byte[] keyBytes = Decoders.BASE64.decode(secret);
        return Keys.hmacShaKeyFor(keyBytes);
    }
    
    // Validate token
    public Boolean validateToken(String token, UserDetails userDetails) {
        final String username = extractUsername(token);
        return (username.equals(userDetails.getUsername()) && !isTokenExpired(token));
    }
    
    // Extract username
    public String extractUsername(String token) {
        return extractClaim(token, Claims::getSubject);
    }
    
    // Extract expiration
    public Date extractExpiration(String token) {
        return extractClaim(token, Claims::getExpiration);
    }
    
    private <T> T extractClaim(String token, Function<Claims, T> claimsResolver) {
        final Claims claims = extractAllClaims(token);
        return claimsResolver.apply(claims);
    }
    
    private Claims extractAllClaims(String token) {
        return Jwts.parserBuilder()
            .setSigningKey(getSignKey())
            .build()
            .parseClaimsJws(token)
            .getBody();
    }
    
    private Boolean isTokenExpired(String token) {
        return extractExpiration(token).before(new Date());
    }
}
```

**JWT Authentication Filter:**

```java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    
    @Autowired
    private JwtUtil jwtUtil;
    
    @Autowired
    private UserDetailsService userDetailsService;
    
    @Override
    protected void doFilterInternal(HttpServletRequest request, 
                                    HttpServletResponse response, 
                                    FilterChain chain)
            throws ServletException, IOException {
        
        final String authorizationHeader = request.getHeader("Authorization");
        
        String username = null;
        String jwt = null;
        
        if (authorizationHeader != null && authorizationHeader.startsWith("Bearer ")) {
            jwt = authorizationHeader.substring(7);
            username = jwtUtil.extractUsername(jwt);
        }
        
        if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {
            UserDetails userDetails = this.userDetailsService.loadUserByUsername(username);
            
            if (jwtUtil.validateToken(jwt, userDetails)) {
                UsernamePasswordAuthenticationToken authenticationToken = 
                    new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
                authenticationToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authenticationToken);
            }
        }
        chain.doFilter(request, response);
    }
}
```

## Chapter 11: HATEOAS & API Versioning

### Q14: What is HATEOAS and how do you implement API versioning?

**Answer:**

**HATEOAS (Hypermedia as the Engine of Application State)** - A REST principle where responses contain links to related resources.

**HATEOAS Example:**

```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @GetMapping("/{id}")
    public EntityModel<User> getUser(@PathVariable Long id) {
        User user = userService.findById(id);
        
        EntityModel<User> resource = EntityModel.of(user);
        
        // Add self link
        resource.add(WebMvcLinkBuilder.linkTo(
            WebMvcLinkBuilder.methodOn(UserController.class).getUser(id)
        ).withSelfRel());
        
        // Add update link
        resource.add(WebMvcLinkBuilder.linkTo(
            WebMvcLinkBuilder.methodOn(UserController.class).updateUser(id, null)
        ).withRel("update"));
        
        // Add delete link
        resource.add(WebMvcLinkBuilder.linkTo(
            WebMvcLinkBuilder.methodOn(UserController.class).deleteUser(id)
        ).withRel("delete"));
        
        // Add orders link
        resource.add(WebMvcLinkBuilder.linkTo(
            WebMvcLinkBuilder.methodOn(OrderController.class).getUserOrders(id)
        ).withRel("orders"));
        
        return resource;
    }
    
    @GetMapping
    public CollectionModel<EntityModel<User>> getAllUsers() {
        List<User> users = userService.findAll();
        
        List<EntityModel<User>> userResources = users.stream()
            .map(user -> EntityModel.of(user,
                WebMvcLinkBuilder.linkTo(
                    WebMvcLinkBuilder.methodOn(UserController.class).getUser(user.getId())
                ).withSelfRel()
            ))
            .collect(Collectors.toList());
        
        CollectionModel<EntityModel<User>> resource = CollectionModel.of(userResources);
        
        // Add self link
        resource.add(WebMvcLinkBuilder.linkTo(
            WebMvcLinkBuilder.methodOn(UserController.class).getAllUsers()
        ).withSelfRel());
        
        return resource;
    }
}
```

**API Versioning Strategies:**

**1. URI Versioning (Most Common):**

```java
@RestController
@RequestMapping("/api/v1/users")
public class UserControllerV1 {
    @GetMapping("/{id}")
    public UserV1 getUser(@PathVariable Long id) {
        // Version 1 returns basic user info
        return userService.findById(id);
    }
}

@RestController
@RequestMapping("/api/v2/users")
public class UserControllerV2 {
    @GetMapping("/{id}")
    public UserV2 getUser(@PathVariable Long id) {
        // Version 2 returns user with additional fields
        return userService.findByIdV2(id);
    }
}
```

**2. Parameter Versioning:**

```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @GetMapping(value = "/{id}", params = "version=1")
    public UserV1 getUserV1(@PathVariable Long id) {
        return userService.findByIdV1(id);
    }
    
    @GetMapping(value = "/{id}", params = "version=2")
    public UserV2 getUserV2(@PathVariable Long id) {
        return userService.findByIdV2(id);
    }
}
// Usage: GET /api/users/1?version=1
```

**3. Header Versioning:**

```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @GetMapping(value = "/{id}", headers = "API-Version=1")
    public UserV1 getUserV1(@PathVariable Long id) {
        return userService.findByIdV1(id);
    }
    
    @GetMapping(value = "/{id}", headers = "API-Version=2")
    public UserV2 getUserV2(@PathVariable Long id) {
        return userService.findByIdV2(id);
    }
}
// Usage: GET /api/users/1 with header "API-Version: 1"
```

**4. Content Negotiation (Accept Header):**

```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @GetMapping(value = "/{id}", produces = "application/vnd.company.app-v1+json")
    public UserV1 getUserV1(@PathVariable Long id) {
        return userService.findByIdV1(id);
    }
    
    @GetMapping(value = "/{id}", produces = "application/vnd.company.app-v2+json")
    public UserV2 getUserV2(@PathVariable Long id) {
        return userService.findByIdV2(id);
    }
}
// Usage: GET /api/users/1 with header "Accept: application/vnd.company.app-v2+json"
```

**Versioning Strategy Comparison:**

| Strategy | Pros | Cons | Recommendation |
|----------|------|------|----------------|
| **URI** | Simple, visible in browser | Pollutes URL | Most common for public APIs |
| **Parameter** | Simple | Not RESTful | Avoid |
| **Header** | Clean URL, RESTful | Harder to test | Good for internal APIs |
| **Content Negotiation** | Most RESTful | Complex | For advanced use cases |

**Interview Tip:** Recommend URI versioning for public APIs as it's most visible and easy for clients. Mention that you can also use content negotiation for more RESTful approach.

```java
@Component
public class DatabaseHealthIndicator implements HealthIndicator {
    
    @Autowired
    private DataSource dataSource;
    
    @Override
    public Health health() {
        try (Connection conn = dataSource.getConnection()) {
            boolean valid = conn.isValid(5);
            if (valid) {
                return Health.up()
                    .withDetail("database", "Connected")
                    .withDetail("url", conn.getMetaData().getURL())

                    .withDetail("database", "Connection invalid")
                    .build();
            }

                .build();
        }
    }
}

            RestTemplate restTemplate = new RestTemplate();
            ResponseEntity<String> response = restTemplate.getForEntity(healthCheckUrl, String.class);

                return Health.up()
                    .withDetail("status", "Service available")
                    .withDetail("responseTime", response.getHeaders().getDate())
                    .build();
            } else {
                return Health.down()
                    .withDetail("status", "Service unavailable")
                    .withDetail("statusCode", response.getStatusCodeValue())
```

## Chapter 14: Profiles & Environment Configuration

### Q17: How do you use @Profile annotation for environment-specific configurations?

**Answer:**

`@Profile` annotation allows you to define beans that are only active for specific environments.

**Profile Configuration:**

```properties
# application.properties (default)
spring.application.name=myapp
spring.profiles.active=dev

# application-dev.properties
server.port=8080
app.datasource.url=jdbc:h2:mem:devdb

# application-prod.properties
server.port=80
app.datasource.url=jdbc:postgresql://prod-db:5432/mydb
```

**Using @Profile:**

```java
@Configuration
public class DataSourceConfig {
    
    @Bean
    @Profile("dev")
    public DataSource devDataSource() {
        return new EmbeddedDatabaseBuilder()
            .setType(EmbeddedDatabaseType.H2)
            .addScript("schema.sql")
            .addScript("data.sql")
            .build();
    }
    
    @Bean
    @Profile("prod")
    public DataSource prodDataSource() {
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl("jdbc:postgresql://prod-db:5432/mydb");
        config.setUsername(System.getenv("DB_USERNAME"));
        config.setPassword(System.getenv("DB_PASSWORD"));
        return new HikariDataSource(config);
    }
}

@Service
@Profile("!test")  // Active for all profiles except test
public class ProductionService {
    // Service logic
}

@Service
@Profile({"dev", "staging"})  // Active for dev or staging
public class DevService {
    // Dev-specific logic
}
```

```java
@Configuration
public class GatewayConfig {
    
    @Bean
    public RouteLocator customRouteLocator(RouteLocatorBuilder builder) {
        return builder.routes()
            .route("user-service", r -> r
                .path("/api/users/**")
                .filters(f -> f
                    .circuitBreaker(config -> config
                        .setName("userServiceCB")
                        .setFallbackUri("forward:/fallback/users"))
                    .addRequestHeader("X-Request-Source", "Gateway"))
                .uri("lb://user-service"))
            
            .route("order-service", r -> r
                .path("/api/orders/**")
                .filters(f -> f
                    .stripPrefix(0)
                    .retry(config -> config
                        .setRetries(3)
                        .setStatuses(HttpStatus.SERVICE_UNAVAILABLE)))
                .uri("lb://order-service"))
            
            .route("product-service", r -> r
                .path("/api/products/**")
                .and()
                .method(HttpMethod.GET)
                .filters(f -> f
                    .requestRateLimiter(config -> config
                        .setRateLimiter(redisRateLimiter())))
                .uri("lb://product-service"))
            .build();
    }
```

**JWT Authentication Filter:**

```java
@Component
public class JwtAuthenticationFilter implements GlobalFilter, Ordered {
    
    @Autowired
    private JwtUtil jwtUtil;
    
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getURI().getPath();
        
        // Skip authentication for public endpoints
        if (path.startsWith("/api/auth") || path.startsWith("/actuator")) {
            return chain.filter(exchange);
        }
        
        String authHeader = exchange.getRequest().getHeaders().getFirst("Authorization");
        
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        
        String token = authHeader.substring(7);
        
        try {
            if (jwtUtil.validateToken(token)) {
                String username = jwtUtil.extractUsername(token);
                
                // Add user context to headers for downstream services
                ServerWebExchange mutatedExchange = exchange.mutate()
                    .request(r -> r.header("X-User-Name", username))
                    .build();
                
                return chain.filter(mutatedExchange);
            }
        } catch (Exception e) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        
        return chain.filter(exchange);
    }
    
    @Override
    public int getOrder() {
        return 0;
    }
}
```

## Chapter 18: Spring Cloud Config Server

### Q21: How do you set up Spring Cloud Config Server for centralized configuration?

**Answer:**

Spring Cloud Config provides server-side and client-side support for externalized configuration in distributed systems.

**1. Config Server Setup:**

```java
@SpringBootApplication
@EnableConfigServer
public class ConfigServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(ConfigServerApplication.class, args);
    }
}
```

**application.yml (Config Server):**

```yaml
server:
  port: 8888

spring:
  application:
    name: config-server
  cloud:
    config:
      server:
        git:
          uri: https://github.com/company/config-repo
          default-label: main
          search-paths: '{application}'
          clone-on-start: true
        bootstrap: true

encrypt:
  key: my-secret-encryption-key
```

**2. Git Repository Structure:**

```
config-repo/
├── application.yml (default)
├── application-dev.yml
├── application-prod.yml
├── user-service/
│   ├── application.yml
│   └── application-dev.yml
├── order-service/
│   └── application.yml
└── shared/
    └── database.yml
```

**3. Config Repository Files:**

```yaml
# application.yml (common configuration)
spring:
  profiles:
    active: dev

management:
  endpoints:
    web:
      exposure:
        include: health,info

# application-dev.yml
spring:
  datasource:
    url: jdbc:h2:mem:devdb
    username: sa
    password: 
  jpa:
    hibernate:
      ddl-auto: create-drop

app:
  name: MyApp Development
  feature-flags:
    enable-new-feature: true

# application-prod.yml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  jpa:
    hibernate:
      ddl-auto: validate

app:
  name: MyApp Production
  feature-flags:
    enable-new-feature: false
```

**4. Config Client Setup (application.yml):**

```yaml
spring:
  application:
    name: user-service
  config:
    import: optional:configserver:http://localhost:8888
  cloud:
    config:
      uri: http://localhost:8888
      fail-fast: true
      retry:
        max-attempts: 6
        initial-interval: 1000
        multiplier: 1.1
  profiles:
    active: dev

# Local override (not in Git)
spring.config.import: optional:file:./local.yml
```

**5. Using Configuration in Client:**

```java
@RestController
@RequestMapping("/api/config")
public class ConfigController {
    
    @Value("${app.name:Default}")
    private String appName;
    
    @Value("${app.feature-flags.enable-new-feature:false}")
    private boolean enableNewFeature;
    
    @Autowired
    private AppProperties appProperties;
    
    @GetMapping("/info")
    public Map<String, Object> getConfigInfo() {
        return Map.of(
            "appName", appName,
            "enableNewFeature", enableNewFeature,
            "databaseUrl", appProperties.getDatasource().getUrl()
        );
    }
}

@ConfigurationProperties(prefix = "spring.datasource")
@Component
@Data
public class AppProperties {
    private String url;
    private String username;
    private String password;
}
```

**6. Refresh Configuration at Runtime:**

```java
@RestController
@RequestMapping("/api/admin")
@RefreshScope  // Allows bean to refresh on config change
public class AdminController {
    
    @Value("${app.feature-flags.enable-new-feature:false}")
    private boolean enableNewFeature;
    
    @PostMapping("/refresh")
    public ResponseEntity<String> refreshConfig() {
        // POST to /actuator/refresh to refresh configuration
        return ResponseEntity.ok("Configuration refreshed");
    }
}
```

**7. Encrypting Sensitive Data:**

```bash
# Encrypt a value
curl http://localhost:8888/encrypt -d mysecretpassword

# Use encrypted value in config
spring:
  datasource:
    password: '{cipher}5a7d8f9e...encrypted-value...'
```
